# Asset Research

> 本技能是**现实调研方法论**，不是事实源，也不定义具体资产类型的生产流程。
>
> 核心原则：**最小充分调研**——只为当前资产的生产决策获取必要的现实证据；不为了填满模板、执行固定步骤或增加来源数量而扩大调研。
>
> 调研结论统一落盘 `docs/research/<asset>-reference.md`。除 D26 允许的占位/测试资产例外外，Research 动作即使被豁免，正式资产仍应形成可版本化的 Reference Spec；Reference Spec 是该资产现实事实的唯一来源。
>
> 工程预算、LOD 面数、性能阈值、Runtime / Shader 实现方案不属于本技能。

## 1. Research Gate

是否需要实际调研，由 `AGENTS.md` 与对应资产 Workflow 按 D26 判定。

Research Gate 先回答：

* 当前现实对象的身份是否已经明确？
* 用户是否已经提供足够的现实事实或参考？
* 本次生产真正依赖哪些现实事实？
* 哪些未知会直接影响当前资产的身份、结构、材质、变体或核心视觉？

Gate 结果不是“必须调研 / 永远不调研”的二元模板，而是确定本次**最小充分证据范围**。

允许按 D26 豁免 Research 动作的情况继续适用：

* 已有 Spec 的派生任务；
* 用户已提供充分参考；
* 占位 / 测试资产；
* 低不确定性、低风险且核心现实特征已有可靠依据。

豁免规则：

* 豁免的是调研动作，不是正式资产的 Reference Spec；
* 用户提供的参考仍应在 Spec 中明确标注来源；
* 占位 / 测试资产按 D26 允许零留痕；
* 不得仅以“常识够用”作为豁免理由。

## 2. 最小充分证据计划

Research Gate 确认需要研究后，先列出**当前生产真正需要确认的现实事实**，再为每一项选择最低成本、足够可靠的证据方式。

事实可以包括：

* 身份 / 定名；
* 关键尺度；
* 结构关系；
* 轮廓与比例；
* 材质与表面特征；
* 真实变体；
* 远近景必须保留的识别特征；
* 其他会直接影响当前生产决策的现实特征。

不要求所有资产都调查所有维度。

例如：

* 普通椅子可能只需确认身份、基本结构和材质；
* 常见路灯可能只需确认结构、比例和材质；
* 高真实度树木可能需要完整结构、叶形、枝姿、树皮、变体等研究。

### 停止条件

当：

> **所有影响当前生产目标的关键事实已经获得足够证据，或继续搜索无法合理降低关键不确定性**

即可停止 Research。

不得为了：

* 填满 Schema；
* 增加来源数量；
* 增加图片数量；
* 消灭所有边缘 Unknown；

而无限扩大调研。

## 3. 证据来源

按事实类型选择最适合的来源：

* 结构 / 尺度 / 专业事实 → 权威文献、官方资料、专业数据库；
* 型号 / 规格 → 官方产品资料、技术文档；
* 形态 / 材质 / 自然变体 → 真实照片、现场资料、专业数据库；
* 3D / CG / 艺术图 → 仅作实现参考，不作为现实事实依据。

来源数量按：

> **当前事实的重要性 + 对象复杂度 + 现有证据充分程度**

决定，不设固定数量。

原则：

* 承重事实必须可追溯；
* 关键事实应尽量交叉验证；
* 单张图片或单一个体不得直接外推为普遍规律；
* 不同证据之间存在冲突时，优先核查来源质量与事实定义，而不是简单取平均或“取中庸”；
* 证据充分时停止；
* 无必要的不确定信息不继续深挖。

按当前领域选择对应的数据端点、静态页面或浏览器通道，不把某一领域的数据源写成通用规则。

## 4. 按需启用专项证据工具

### 4.1 照片验证

仅当照片承担以下任一现实主张时，才加载：

`references/photo-verification.md`

* 身份判定；
* 关键结构判定；
* 关键比例 / 尺度判定；
* 其他会直接影响当前生产决策的视觉事实。

普通参考图仅用于观察、定调、对照时，不强制执行照片验证规程。

### 4.2 关键数值独立抽查

仅对：

> **会影响当前身份、结构、核心比例或生成决策的关键数值**

执行主代理独立抽查。

无承重作用的次要数值不要求逐项重新核对。

## 5. 提取与转译

来源事实必须转译为后续开发可消费的现实描述：

* 数值；
* 范围；
* 结构关系；
* 相对关系；
* 可观察特征。

禁止：

* 凭经验补造现实事实；
* 用其他资产的参数直接替代当前资产事实；
* 把工程参数伪装成现实事实；
* 把视觉印象伪装成精确数值。

参考图可暂存于：

`screenshots/ref-tmp/`

不得进入产品运行时与 Git。

## 6. Evidence Status

关键事实使用：

```text
Verified
Inferred
Unknown
```

三者含义：

* `Verified`：有直接、可靠证据支持；
* `Inferred`：有可靠证据支撑，但当前结论包含合理推断，不能视为直接测得事实；
* `Unknown`：现有证据不足以可靠确认。

**证据不足不得自动降级为 Inferred。**

事实表达形式独立标注：

```text
Value
Range
Relative
Qualitative
```

两轴互不替代：

```text
Range ≠ Inferred
Value ≠ Verified
Qualitative ≠ Unknown
```

示例：

```text
- 树高：7–9m
  - Form: Range
  - Evidence Status: Verified
  - Source: [1]
```

## 7. Unknown Gate

仅当 Unknown 会影响当前生产目标时才阻塞：

* 身份；
* 结构；
* 形态；
* 材质；
* 变体；
* 核心视觉表达。

处理方式：

* 能继续获得高价值证据 → 继续研究；
* 继续研究也无法可靠确认 → 保留 `Unknown`；
* 报告主代理；
* 由主代理决定该 Unknown 是否允许带入工程实现；
* 边缘性 Unknown 可记录但不阻塞。

不得为了消灭所有 Unknown 无限补研。

## 8. Reference Spec

按：

`references/spec-template.md`

写入：

`docs/research/<asset>-reference.md`

Reference Spec 采用：

> **通用骨架 + 按需领域字段**

而不是固定问卷。

规则：

* 相关事实就写；
* 不适用字段可以省略；
* 关键但无法确认的事实标 `Unknown`；
* 不得为了填满模板而补造事实；
* 领域 Schema 是允许描述哪些现实维度的工具，不是每个资产必须完成的调查清单。

## 9. Domain Schema

已有 Domain Schema：

> 按当前资产生产真正需要的字段选取填写。

新领域首次出现：

> 允许先起草 Schema 草案，由主代理审阅后纳入。

Schema 定义现实领域字段，不反向服从当前代码实现。

## 10. 交付自检

正式资产完成 Research 时：

* [ ] Research Gate 已判定并留痕
* [ ] 已确认当前生产真正需要的现实事实
* [ ] 承重事实有可追溯来源
* [ ] 关键事实 Evidence Status 正确
* [ ] `Inferred` 仅用于有证据支持的合理推断
* [ ] 关键 Unknown 已处理或明确报告
* [ ] 无伪精确工程数值
* [ ] 现实事实与工程设定分离
* [ ] 需要时执行照片验证 / 关键数值抽查
* [ ] Reference Spec 可被后续开发 Agent 直接消费
* [ ] 已达到停止条件，没有为填模板而继续扩展 Research

## 11. 边界

本技能：

* 只负责现实调研；
* 只产出 Research / Reference Spec；
* 不写产品代码；
* 不决定 Geometry / Shader / LOD / Runtime 实现；
* 不替代资产 Workflow；
* 不替代最终视觉验收。
