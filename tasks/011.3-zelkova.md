# T011.3 榉树全链（第三树）

> 归属：[T011 第一批阔叶乔木](011-broadleaf-trees.md) ｜ 状态：**todo（2026-09-20 立项起草）** ｜ 前置：T010 5/5 + T006 5/5（epic 级前置）+ 011.2 done（固化流程两轮验证）；**本任务起 Step 4 按 D30 增量口径（新口径首跑）**

## Goal

榉树（Zelkova，榆科榉属——具体种由 Spec 调研确认）生产资产 `asset_tree_zelkova`：Research Gate → Reference Spec → 阔叶家族契约实例化 → 几何 / 材质 / 8 槽形态向量 / LOD 三档 / Shadow 通道 → **D30 增量视觉验证**（身份判定 + 基线帧 + 缺口记档三必做）。第四种树皮语言（光滑片状剥落 vs 夏栎脊沟 / 朴树浅斑 / 香樟纵裂）+ vase 形冠（上宽下窄杯状读向）——形态语言与三先例分化最大的落叶阔叶实例，继续发现并记档家族契约缺口（默认零修订、归 011.5 族级收口；阻塞缺口例外见 Constraints，D31.2）。

## Research Gate 判定（D26，开工前留痕）

- **判定：强制调研**。命中情形同 011.1/011.2：①高真实要求（树种辨识度以 Spec 身份/识别特征节为判据）；②类型显著影响形态（榉树 vs 三先例：vase 形冠 + 树皮光滑片状剥落 + 叶基偏斜桃形 + 叶缘单锯齿尖齿——换色复用 prohibited）；⑤资产将成同类生产基准。
- **执行**：通用子代理加载 asset-research 技能 → `docs/research/zelkova-reference.md`；主代理硬数值独立抽查 + 照片终审（008.6 返修规程：候选照片 URL 自 API JSON 提权威扩展名、两次独立视觉提问一致方定名）。
- **Spec Version 锚点：1.0**——开发 Agent 开工前校验任务书引用版本与 Spec 顶部一致。

## Requirements

- **Step 0 调研落盘**：八节骨架 + plant 域扩展节（plant-schema v0.2）；两轴标注（Form / Evidence Status）；结构尺度 → 植物志（FRPS/FOC 优先），形态材质变体 → 真实照片直接视觉证据；Unknown 显式留档。重点调研面：种定名（光叶榉 Z. serrata vs 大叶榉 Z. schneideriana——中国公园语境）、**vase 形冠结构成因**（侧枝开张上举的分枝语言）、**树皮片状剥落**（光滑灰白皮 + 薄片剥落斑驳——vs 三先例第四种；浮雕层表达口径需调研）、叶形（卵形/卵状披针形 + **叶基偏斜**（榆科核心辨识）+ 叶缘**单尖锯齿** vs 朴树钝锯齿）、叶脉（羽状脉直伸齿尖）、分枝结构（细枝密平展？）、秋色叶不建模（epic 语境为中龄公园常绿态观感——以 Spec 定）。
- **Step 1 结构分析**：Spec → 三先例方法基线对照——可继承项 / 按榉树改写项 / Unknown 项；每条改写映射实现面。
- **Step 2 参数化**：`tree/zelkova/zelkovaShapeProfile.ts`——BroadleafShapeProfile 填榉树数值，逐字段 Spec 依据 + Evidence Status + 三标注（【家族共性候选】/【榉树特有】/【工程设定】）；结构计数类跨槽恒等；slot-0 锚点 + 7 槽差量展开（009.3 语法）。
- **Step 3 几何（procedural-asset-agent）**：`tree/zelkova/zelkovaGeometry.ts`——方法复制 + 榉树算法细节（干形/冠形/枝姿/树皮起伏按 Spec 与 profile——vase 冠缘上举收口、片状剥落光滑皮的起伏语言表达）；LOD 三档同流（同 rng 流 / Mid⊂High 掩码 / Low 簇位壳卡）；入口 `assets/asset_tree_zelkova.asset.ts`（meta：taxonomy broadleaf / shapeFamily 8 / levels 三档 / triangleCount = slot-0 High 实数 / proceduralProfile 全槽实测带；build slot→profile 路由 + level 透传 + customDepthMaterial 契约通道）。
- **Step 3 材质（park-shader-agent，与几何文件集不相交并行）**：`tree/zelkova/zelkovaMaterials.ts`——榉树叶 SDF（卵形 + 叶基偏斜 + 单尖锯齿——以 Spec 叶形节为准）+ 叶色双面区分 + 背光透射 + 风动两层（aSeed/aBend 沿用）+ 树皮配方（光滑片状剥落斑驳——vs 三先例第四种树皮语言）+ 深度材质同源 GLSL + 9 键分档。
- **Step 3 DEV 出图面（threejs-runtime-agent，合并后）**：`tree/zelkova/zelkovaStage.ts`——mountSlots / view / mountLevels 同构（import.meta.env.DEV 守卫）+ bootstrap 挂载 `window.__zelkova`。
- **Step 4 视觉验证（主代理，D30 增量口径）**：三必做——①Spec 身份判定记档（对照 Spec「身份/识别特征」节出结论）；②统一基线帧 `baseline.png`（M25（25m/35°/8°）+ day 预设固定灯光 + freezeTime，落 `docs/acceptance/t011/011.3/`——全族同参数，兼用户观感复核窗口与 011.5 族门横向同源基线）；③契约缺口记档（有无都记，归 011.5）。余按疑点触发（十项检查单为疑点对照清单非必跑清单：多机位取证/离屏探针/风动三证据/console 回读/LOD 档间复查——由身份判定疑点或开发 agent 自检信号触发）；校准默认一轮、两轮封顶，疑似结构性问题上收 011.5 记族级契约缺口（011.2 envMap 先例）；终态复拍只拍受影响机位 + 一张基线帧。
- **测试**：对称 camphor/celtis 组织（tests/runtime/procedural/tree/zelkova*）——Structure / Lod / Materials / ShapeSlots / Stage + 入口 meta/路由。
- **验收基线**：预算 = 家族行 High ≤40000 / Mid 6000–10000 / Low 1500–3000；夏栎/朴树/香樟/GLB/旧资产零变化（既有测试全绿即证）。
