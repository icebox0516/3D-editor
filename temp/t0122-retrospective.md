# T012.2 水杉 执行流程复盘报告（2026-09-29，单会话全链 + 两次配额中断）

数据源：temp/t0122-metrics.md（全程时间线 25+ 条）；子代理时长以 usage 数据为准（自报三次失准）。

## 一、实际流程耗时与资源

- 墙钟 11:48–19:45 ≈ **7h57m**；有效工作 ≈ 5h27m；**配额阻塞 ≈ 2h30m**（13:39–15:49 用户恢复 + 17:24–18:18 提前释放）。
- 子代理 10 次派遣（3 次死于 5h 配额上限）：调研 53m｜Step2 17.8m｜3a 原派 26m†｜3b 原派 26m†｜3a 恢复 9.7m｜3b 恢复 23.1m｜3c 36.9m（24.3M tokens，最大）｜调试派遣 19m†（留下未报告 SDF 修复）｜校准 37m｜裁定 7m（†=死于配额）。
- 主代理环节：立项 5m｜终审 12m｜Step1 5m｜Step4 取证+缺陷诊断 ~70m（含阻塞期只读诊断 33m）｜复拍+判定+收口 ~45m｜三门槛+同步+提交 ~20m。
- 产出：实现 4843 行（几何 1530/材质 815/profile 571/Stage 471/入口 177/契约转正）+ 5 测试件净 123 用例（4524 全绿）+ Spec 197 行 + 取证 26 帧 + 契约草案→定稿 80 位。
- 返工计数：密度校准 1 轮（结构性预判失误）；恢复重验 2 次代理交付 + 1 次死代理残留；无效探针 2 次（build() 返回结构误判）；恢复简报误诊 2 次（均零损失）。

## 二、各环节必要性（事实观察）

- **Research Gate + 主代理终审：必要且高性价比**——12 分钟终审抓 3 处真实偏差（照片承重撤回 1 处/读数精化 2 处）；文字源 10 锚逐位全对说明调研文字面可信，抽查密度 5–8 项恰当。
- **Step 1 结构分析：必要且第二例起成本骤降**——族内先例索引摘要足够（原任务书零回读，5 分钟 vs 012.1 需跨族导航）；但本环节产出的 11 条判定中 1 条（卡尺度杠杆不适用）被像素证伪——判定质量直接决定下游校准成本。
- **专业派遣（3a∥3b 不相交并行 + 3c）：必要**——文件集纪律执行良好；恢复重验抓出器官帧错组契约级缺陷（球果会渲染成树皮条纹），静态测试全绿下只有重验/像素能发现。
- **Step 4 三必做 + 疑点触发：必要**——本轮抓到叶卡不可见真实缺陷并完成单根因终诊；增量口径 26 帧合理（含诊断追加）。
- **契约草案-转正机制：顺畅**——72→80 位一次转正，零阻塞修订，cedrus 零行为变化回归锁全绿。
- **中断即未验证纪律：两次兑现真实价值**（器官帧错组 + 未报告 SDF 修复重验）。

## 三、冗余与重复

- 事实：全量 npm test 在 3b 恢复/校准/裁定/主代理收口共跑 4+ 轮（75s/轮）；3c 与 Step 4 重复做视觉判读（且 3c 一帧判读将叶卡不可见误读为「密度偏低 5–15% 裸枝」——非像素判读不可靠）；Step 2 与 3a 同代理两次 read-set 装载（契约+任务书重复 full-read）。
- 流程问题：全量回归的职责归属（收口轮归主代理）在简报中未显式声明；3c 简报含「一帧判读」任务却没有像素工具约束。
- 优化建议：简报模板明确「定向自跑 + 全量归主代理收口轮」；3c 视觉判读职责移除或强制落盘帧+像素量化；Step 2+3a 合并派遣（012.1 已有同代理连续先例）。

## 四、复杂度是否匹配

- 事实：水杉 = 中等偏复杂资产（增量口径 + 转正职责），全流程 6 环节对此恰当；唯一失配点 = 密度初判（Step 1 有意放弃卡尺度杠杆导致 Step 4 校准一轮——两例连续证明「初版密度预估系统性偏低」是方法级规律而非个案）。
- 流程问题：012.1 的密度校准教训因 D40 单实例纪律未进 workflow 正文，012.2 重复踩坑（若已泛化可省 ~1h + 2 次派遣 + 1 次终诊）。
- 优化建议：tree workflow §Step 2/3a 加「初始密度目标 = 预算带 80–95% 用满 + 卡尺度 ≥0.3m 杠杆普适（两例实证）」——这正是 D40 纪律设计的升格路径：第二实例已出现，四问筛选器应放行。

## 五、调研是否过重

- 事实：调研 53m 占子代理总时长 ~18%，文字源 5 个/照片 12 张（弃用 2）；环境事故 2 起自处置（API 配额→curl；直链解析→CDN 中转）。
- 判定：**不过重但有可省面**——照片双问弃用率 2/12 说明候选预筛不足（分辨率/主体占帧比预筛可省 30–40% 双问成本）；文字源数量恰当（强源 4 + 弱源交叉 1）。
- 优化建议：asset-research 技能加照片预筛判据（不入正文数值、只入方法步）；不强砍承重槽数量（9 槽全消费）。

## 六、测试/验收是否过重

- 事实：净 123 用例（slots 23 + structure/lod 55 + materials 45），D40 五者准入执行良好（无公共能力复制）；雪松回归锁 108/108 三轮复验；视觉 26 帧 + 像素量化 8 轮 + 双问 6 次。
- 判定：**测试面不过重、执行面有冗余**（全量多轮，见三）；视觉验收深度恰当（抓到真缺陷本身证明其必要——不是为规则而跑）。
- 优化建议：见三（全量轮次收敛）；验收判据表加像素量化数值列已是实际做法，应成文进 workflow §Step 4。

## 七、Skill / Workflow / Spine 是否合理

- 事实：入口路由 → spine → tree workflow 三层共 ~330 行正文，本轮全程零规则冲突、零 read-set 违规；012.1 教训「隐式接口显式冻结」成功转化为 Step 2 产出物并在 3a∥3b 间生效（虽被中断前任静默偏离，由 3b 重验对齐）。
- 流程问题：①spine「中断即未验证」只有原则无操作协议（本例自创的「重验+补缺」恢复模式效果好但每次即兴）；②经验升格滞后（密度规律两例后才具备泛化资格——这是 D40 设计使然，属制度成本而非缺陷）；③spine 无子代理回传数据规范（时间三次自报失准）。
- 优化建议：spine §1 补中断恢复操作清单（4 行）；workflow 补密度前置目标；回传格式固定「usage 级时长 + 关键量化数字」。

## 八、子代理职责与派遣

- 事实：路由零失误（几何/参数→procedural-asset、材质→park-shader、运行时→threejs-runtime、调研→通用）；专业面零重叠；3a∥3b 文件集不相交执行良好；唯一跨界 = 死调试代理改了材质文件（正确归属）但未报告。
- 流程问题：①配额上限 vs 单资产全链 6–8h 的结构性冲突（两次中断、3 次派遣报废/半报废）；②恢复派遣的简报缺口定位两次误诊（「canopy 缺行」「死代理零改动」——远程盘点基于 git status，看不到未跟踪文件内容）。
- 优化建议：派遣批次尽量避开配额窗口尾部（会话级感知）；恢复简报把「断言」降级为「假设 + 待代理核实」；恢复盘点清单 = 未跟踪文件 mtime + 定向测试红名单 + 残留进程。

## 九、read-set / 上下文膨胀

- 事实：主代理启动读集 5 文件 ~330 行（合规精简）；各 Step read-set 均按 workflow 表解析下发；无「可能相关」扩读；3c 单代理 24.3M tokens（141 工具调用——运行时验证 + headless 链路是重头）。
- 判定：read-set 机制运转健康、无膨胀违规；上下文压力点在运行时验证类代理（dev server + CDP 驱动天然多轮）。
- 优化建议：3c 类验证代理的回传应压缩为结论+计数表（本例 3c 回传 ~4K 字含大量过程叙述——审查有效但可瘦身）。

## 十、中断恢复

- 事实：两次配额中断处置——第一次（3a∥3b 死）：盘点→定向测试探完成度→「重验+补缺」恢复代理×2→全绿；第二次（调试代理死）：主代理只读诊断 33m（不违派遣硬约束）→校准简报落盘→重置后派遣。
- 判定：恢复模式有效（恢复代理成本仅原派遣 1/3；死代理产出 90% 可用）；「中断即未验证」价值两次兑现。
- 流程问题：恢复盘点靠 git status 漏检未跟踪文件内的死代理改动（由校准代理暴露）；死代理清理误杀主代理进程实例一次。
- 优化建议：恢复盘点清单化（见八）；代理进程清理纪律加「只清自己起的」（正文已有惯例、恢复简报应显式重申）。

## 十一、实际产出价值

- 对本资产：水杉全链可交付（身份 8 要素判定成立、三档预算全落锁行、双卡、风动、canopy 接线、console 零噪声）。
- 对家族：契约转正定稿（后续成员增量消费）；三杠杆普适化实证；骨架族内变体两型（方位律/密冠）入先例索引；落叶双卡模式首例（针叶族）。

## 十二、具体卡点与踩坑（事实清单）

## 十三～十六、可删除 / 可合并 / 下沉上提 / 保留不动

- **可删除**：3c 的视觉一帧判读（职责归 Step 4 像素）；恢复/校准代理的全量 npm test（定向即可）；诊断期 2 次无效探针（读签名可免）。
- **可合并**：Step 2 + 3a 合并派遣（同代理、read-set 大量重叠、012.1 先例）；3c 的 GLSL 编译验证可前移并入 3b 收口（若 3b 获授权拉 dev server）——保守项，保持现状亦可。
- **应下沉（正文化）**：密度前置目标（workflow §Step 2/3a，两例实证已够格）；像素量化进 Step 4 判据表规范；canopy 取证机位规范（过渡带外 + distribution 探针）。
- **应上提（spine）**：中断恢复操作清单；子代理回传数据规范（usage 时长）。
- **建议不动**：三门槛判据式（D40）；Research Gate 逐树独立 + 主代理采样终审；D30 三必做+疑点触发分层；契约草案-转正（D37）机制；专业派遣路由与文件集不相交纪律；中断即未验证原则；先例索引「方法摘要+导航」定位。

## 十七、建议修改的最小变更（按影响×成本排序）

1. **tree workflow §Step 2/3a 前置密度目标**（预算带 80–95% 用满 + 卡尺度 ≥0.3m 杠杆普适）——影响：省每资产 ~1h + 2 派遣；成本：改 3 行。
2. **spine §1 中断恢复操作清单**（盘点 = 未跟踪 mtime + 定向红名单 + 残留进程；恢复 = 重验+补缺模式）——影响：恢复成本再降 + 杜绝漏检；成本：加 4 行。
3. **派遣简报模板：全量测试归主代理收口轮 + 回传含 usage 时长 + 恢复缺口写假设**——影响：省 3×75s×N 轮 + 数据质量；成本：模板 2 行。
4. **3c 简报去视觉判读、强制落盘帧 + 像素工具**（或并入 Step 4 首拍）——影响：消除误读源；成本：改简报。
5. **Step 2+3a 合并派遣**——影响：省一次 read-set 装载（~10m/资产）；成本：workflow Step 表 1 行注记。
6. **asset-research 照片预筛判据**——影响：省 30–40% 双问；成本：方法步 3 行。

## 四问总结

1. **真正必要**：Research Gate+终审、Step 1 先例判定（族内第二例起尤其廉价）、专业派遣与文件集纪律、三必做视觉验收（像素化）、契约草案-转正、中断即未验证、三门槛。
2. **明显过度**：全量测试多轮、3c 视觉判读重复、照片双问无预筛、（制度层）经验升格的实例数门槛导致密度规律延迟一轮生效。
3. **随资产数继续膨胀**：共享面机械增行（~6 处/资产）、契约字段位（80→+5-10/例）、先例索引（良性资产）、调研线性成本、单资产全链时长逼近配额上限（恢复开销随之中升）。
4. **下一版最应该改**：前置密度目标进 workflow（1）；中断恢复协议进 spine（2）；派遣简报三条款（3）——三条合计每资产省 ~1.5h 且不削弱任何质量门槛。
