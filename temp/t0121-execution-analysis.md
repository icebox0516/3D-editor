## 4. 返工与对齐点分析（9 项逐条）

根因分类口径：**产出质量缺陷**（上游交付物错了）/ **接口设计缺口**（派遣冻结不完整）/ **参数校准必然性**（新形态语言的发现成本，任务本质）/ **环境事故** / **执行事故**（含主代理自身）。

### ① childPlan 数据行笔误 —— 产出质量缺陷（Step 2 质检缺口）

- 事实：Step 2 产出 childPlan 数据行 `3/3/3/2`（阔叶模板拷贝痕）与自身模块头算术 `[2,2,2,2]` 自相矛盾；3a 探针按字面消费后发现皮面 70198 越带 75%，按模块头算术修正后实测 28142 回预估带。
- 成本：嵌入 3a 首轮（探针绕路 + 修正），估计占 #2 段的 5–10%（约 1–2M token 量级，无法精确切分）；外加主代理例外复核一次。
- 可预防性：**高**。Step 2 的 17 例测试若含「模块头算术摘要 vs 数据行一致性 / 拓扑展开断言」即可拦截。完成记录已四问筛选记为候选流程教训②（单实例未泛化，D40，本轮不改 workflow 正文——处置正确）。
- 值得肯定面：探针驱动拦截回路本身按设计工作（越带 75% → 修正 → 回带 → 主代理复核），笔误未流入合并。

### ② 针卡双帧 uv 并行接口缺口 —— 接口设计缺口（最大的一笔纯返工）

- 事实：3a/3b 对针卡 uv 帧域各自实现（3a 统一 {0,1}；3b 按散生 v∈[0,1) / 莲座 v∈[2,3) 双帧）；3b 实测发现，合并阶段由 3a-resume 补对齐（含 Low 壳卡帧判定、双帧域测试、隔离带开区间修正——4566/1380 合法端点顶点经 uv 直方图探针定位误判）。
- 成本：#4 段全额 **8.33M token / 8.5 分钟**（该段同时承载③的边际很小）+ 3b 侧发现成本（嵌入）+ 主代理协调裁决。
- 可预防性：**高**。派遣冻结接口只声明了显式签名（材质三工厂），未覆盖隐式接口（uv 帧域 / attribute 语义）。冻结接口清单化即可。已记候选流程教训①。
- 归因注记：并行 Step 省下的墙钟（3a∥3b 重叠 23 分钟）与本次对齐成本（8.5 分钟 + 协调）相抵后并行仍为正收益，**不能由此否定并行结构**——但隐式接口清单能让下次并行干净落地。

### ③ swatch 同源微差 —— 接口设计缺口（冻结了「值」而非「推导规则」）

- 事实：派遣时冻结初值 0x6b8a72，3b 实际构造中点 0x6b8273（ΔG8）；按 T024 三处同源纪律回写 meta / CROWN_PRESETS / 测试锚。
- 成本：三处回写，边际很小（嵌入 #4 段）。
- 可预防性：**高**。冻结「swatch = 叶构造色中点」的推导规则而非具体数值，或派遣时按公式预计算。同类问题在 T024.3 批次出现过（swatch 三处同源纪律的来源），属**已知教训在新上下文的再发生**——冻结面从「哪些位置同源」升级到「以什么规则同源」后才算真正闭合。

### ④ 密度校准两段 —— 参数校准必然性 × 执行损耗混合（最大成本项）

- 事实链：六帧独立判读一致偏疏（B25 透天 90–95%）→ 第一段散生针卡线密度 4→9 浅调，实测无效（覆盖率 14.7→17%）→ 第二段根因定位（单面卡无角度覆盖 / 卡尺度亚像素〔0.10–0.16m 卡在 M25 仅 3–4px〕/ 枝上裸段三因）→ 交叉双卡 + 卡尺度×3（0.30–0.44m）+ 挂点前移 + 预算再分配 → 复判三面达成 + 量化（M25 冠区 14.7→33.0%，B25 透天→25–35%）。
- 成本：**45.17M token / 82.5 分钟 / 114 次调用 = 全部子代理成本的 45.3%**。拆分：
  - 一段（#6）14.47M：**执行损耗为主**——未诊断先调参，调的是最便宜的旋钮（线密度），而根因（卡尺度亚像素 + 单面无角度覆盖）根本不在该旋钮的作用面上。若一段前先跑密度图 + 近景探针（二段实际做的事），这段大概率可省。
  - 二段（#7）30.70M：**任务本质难度为主**——针叶簇卡在 M25 距离下的密度物理是阔叶族从未遇到的现象（阔叶卡面大、无此问题），三因根因属发现型工作；预算再分配（单针卡撤预算给簇）+ 全量测试重锁（High 带 32224–38382 重锁、rng 快照 32507→37764）+ 会话内自建无头 Chrome 量化链，都是首例的合理成本。其中「自建量化链」部分可通过工具前置摊薄（§6-6）。
- 可预防性：一段**高**（先诊断后调参纪律）；二段**中低**（新形态语言的首例发现成本，D30 校准护栏本身预期了「一轮」；实际一轮内两段收敛，未破两轮封顶）。
- 增值面：终局产出不止修好了本资产——「中距浓密板三杠杆」（交叉双卡 / 卡尺度 ≥0.3m / 挂点前移）已入 precedents/conifer.md 索引，后续针叶成员直接继承先验。

## 5. 工作量结构归因

### 5.1 三类归因的占比判断

**口径：以本会话子代理 99.7M token 为分母（前会话无数据，主代理无 token 口径，二者单独说明）。**

| 归因类 | 构成 | token | 占比 | 论据 |
|---|---|---|---|---|
| **A. 流程设计的必然成本**（每例资产按纪律都要付的） | Step 2 全额 + 3a/3b/3c 首轮的主体 + 主代理全部七类动作 | ≈40–46M | **≈40–46%** | 四槽专业派遣、每 Step 全新实例（上下文重建的 read-set 全量自读）、Step 4 完整取证链、三门槛四轮——全是 AGENTS.md / spine 明文设计的成本。**这部分不是浪费，是本项目用冗余换质量与可审计性的既定选择** |
| **B. 任务本质难度（新 Family 首例一次性）** | 校准二段主体 + 3a/3b 中的新语言溢价 + 契约草案创建 + precedents 首建 + 完整首例验收深度（相对增量口径的差量） | ≈35–42M | **≈35–42%** | ①契约从零：67 字段草案无任何先例可实例化；②形态语言全新：莲座簇 SDF / 层状骨架 / 无两面色差 / 树皮第 14 语言——3a 21.2M 中按「族内复制-改写」基准估算有 30–40% 新语言溢价（推断值）；③密度现象发现：30.7M 校准二段；④D37 六步 + D30 完整首例验收相对增量的差量（39 帧取证 vs 三必做） |
| **C. 执行损耗**（同类任务可避免） | 校准一段全额 + 合并对齐全额 + 嵌入式小损耗 + 主代理判读返工 | ≈23–26M 子代理 + 主代理时段 | **≈23–26%** | ②③接口缺口 8.33M 是派遣简报可闭合的；④一段 14.47M 是「先调参后诊断」顺序错误；①⑧是产出/自检不一致的低级缺陷；⑤⑥⑦环境事故约 1–3M |

**交叉验证**：A+B+C 区间并集 ≈ 99.7M，三类边界互有渗透（如校准二段中约 10–15% 属可由工具前置摊薄的成分，归在 B 但可向 C 转移预防）。

### 5.2 99.7M 的分布解读（计费结构，不是有效产出）

- **分布极度不均**：四段「首过交付主干」（#1/#2/#3/#5）合计 46.2M（46.3%）；三段「3a-resume」（#4/#6/#7）合计 53.5M（53.7%）——**返工与校准全部发生在 resume 长会话里，而 resume 段单调用计费 37.7 万，是新鲜实例（15.6 万）的 2.4 倍**。即：返工不仅本身耗 token，还因发生在长上下文会话中被计费结构二次放大。99.7M 里约 30M+ 是上下文重复计费，不是新生成的推理或代码。
- **性价比最高的一段**是 Step 2（#1）：1.6% 的 token 完成了 296+547+258 行契约与实例化（含 17 测）——因为任务边界清晰、read-set 干净、无探针循环。
- **性价比最低的一段**是校准一段（#6）：14.5% 的 token 买到的有效变更是一个实测无效的参数浅调。
- **量级感**：99.7M 计费 token 对应约 5845 行代码+测试与 31 帧取证——**约 1.7 万 token/行的计费密度**。此数字仅说明「多轮探针循环 + 长会话修复」模式下计费远超代码量，不能读作生产率（代码行也不是产出价值的度量）。

### 5.3 前会话与主代理（无数据部分的定性）

- 前会话（Step 0/1）：产出为 Spec 165 行 + 判定 10 条 + 立项文档 140 行，均为文档型工作；参考 3b 段（8.1M，含 684 行代码 + 46 测）的量级，前会话成本估计在个位数 M token 量级（**无数据，纯推测，不计入上文占比**）。
- 主代理：七类动作中，验证类（39 帧取证判读 + 4 轮回归 + 重验）估计占其时段大头；派遣设计与合并协调是高杠杆动作（3 次简报决定了 7 个子代理段的边界质量——②号事故正出在简报的冻结面上）。

## 6. 效率观察（不改项目纪律前提下的可优化机会）

按预期收益排序；每条标注收益与风险。全部基于本链证据，已在完成记录记档的教训不重复展开。

1. **派遣冻结接口清单化（含隐式接口）**——防 §4-②③。冻结面从「显式签名」扩到固定清单：uv 帧域 / attribute 语义 / 派生值规则（swatch=构造中点之类）。收益：消除本次 8.33M（8.4%）量级的并行对齐成本，且为 012.2 起每次 3a∥3b 并行复利；uv 帧域已在缺口 #2 挂「可升家族契约字段」。风险：清单膨胀造成简报噪音——只列并行面真正共享的项即可。
2. **校准「先诊断后调参」纪律（量化指标前置）**——防 §4-④一段。密度疑点成立时，第一动作固定为密度图探针 + 近景尺度探针（本例二段实际做的事），量化指标（冠区非天空占比 / 透天率）在调参前先建基线。收益：本次可省 14.47M（14.5%）；风险：像素指标与观感可能背离（本例 M25 占比与判读同向，但真正的判据是 B25 透天与 M8 星芒）——指标只做定位器，多帧判读保持终裁。
3. **Step 2 参数面自检断言**——防 §4-①。模块头算术摘要 vs 数据行一致性断言 / 拓扑展开皮面数断言，几行测试。收益：消灭笔误类拦截绕路（本例约 1–2M + 复核）；风险：几乎无。
4. **判读记档以工具返回为依据**——防 §4-⑧。无真实返回的判读不写入判据表。收益：消除承重帧补判返工与证据链风险；风险：无。
5. **dev server 单例纪律 / 校准会话缓存隔离**——防 §4-⑤⑥。收益：小（每次事故量级小），但发生在 resume 段时被计费放大，且打断取证流；风险：无。
6. **量化链工具沉淀**——3a 校准二段会话内自建的无头 Chrome 逐行天空参照覆盖率探针，若升级为 tools/ 常设脚本（与已入库的 pixel-diff.mjs / cdp.mjs 同级），012.2 起疑点量化直接可用。收益：摊薄后续每例校准的建链成本（本次嵌在 30.7M 段内）；风险：工具维护面小幅增加。
7. **校准实例策略（待验证假设，非建议）**：计费结构显示 resume 长会话单调用计费 2.4 倍——「校准开新实例 + 紧简报（携带诊断结论与探针指令）」可能比「3a-resume 继续」便宜。但本例根因定位的深度恰恰依赖 3a 对自家几何的上下文（交叉双卡方案是理解 emitCard 实现后给出的），新实例可能多花诊断轮次。**列为假设**：等 012.2 真实校准场景出现时 A/B 一次再定。
8. **（轻）主代理全量测试轮次**：4 轮 ×78s ≈ 5 分钟机器时间，各轮锚点（合并后 / 校准后 / 终态）均有依据，收益上限小——维持现状合理，仅在「无代码面变化的纯文档轮」可免跑 npm test（三门槛判据式本就如此）。

## 7. 结论

**一句话回答**：T012.1 工作量大的主因是新 Family 首例三重一次性成本的叠加——契约与形态语言从零（含莲座簇 SDF、层状骨架等无先例可复制的新语言）、D30 完整首例验收深度（39 帧取证 + 全项疑点）、密度新现象的发现式校准（45.3% 的子代理 token）——其中纯执行损耗约占 23–26%（盲调一段 14.5% + 并行接口缺口 8.4% + 嵌入式小损耗与主代理判读返工），流程必然成本约四成，且全部 token 数字受 resume 长会话计费放大（约 54% 的 token 发生在三段 resume 里）。

**后续成员会便宜多少（D30/D37 增量口径推断）**：

- **不再付的一次性成本（本例 ≈50% 量级）**：契约草案创建（012.2 起消费既有草案，修订走转正轻量路径）；precedents/conifer.md 首建（只加行）；完整首例验收 → 增量口径（三必做 + 疑点触发）；密度三杠杆先验 + 量化链（校准预期归零或缩为小校准）；uv 帧域 / swatch 推导等接口学费。
- **每树不可压缩的常量**：Step 0 逐树独立调研（Spec 不可复用）、3a/3b/3c 实现主干（本例四段首过交付 46.2M 是同复杂度树的参考下限）、三必做取证与三门槛。
- **估算**：同复杂度针叶成员（如云杉/冷杉类尖塔树形）子代理成本约 **40–55M token、墙钟约 2 小时上下**（本例的 50–60%）；树形更简单的成员（柱形圆柏/龙柏共骨架）更低；引入新叶型语言的成员（水杉类条形叶、落叶季相）会局部反弹但不再从零。此为推断值，±20% 不确定度，以 012.2 实测校准。

**最锋利的一个数字**：如果把校准一段（盲调 14.47M）和合并对齐（8.33M）两笔可预防损耗拿掉，本例子代理成本是 76.9M 而不是 99.7M——**约 23% 的工作量花在了本可避免的返工上**，而其中大部分的预防手段（冻结接口清单、先诊断后调参、自检断言）成本几乎为零，且已全部在本任务完成记录中留档为候选流程教训，待第二例验证后升格。
