> 本版由 2026-09-11 grilling 拷问会话（9 问 + 复核）与用户逐题确认后定稿，取代初稿（v1）中与之冲突的一切表述。
> 初稿中被否决/修正的要点见文末「v1 → v2 变更对照」。本文档是阶段 6（形状驱动创建与样式引擎重构）任务书的唯一需求来源。

## 一、核心目标：两套创建模式

编辑器只有两条对象创建路径，彻底取代旧「六类要素各建各的」模式：

1. **绘制模式（本方案）**：用户先在视口绘制纯几何形状（多边形 / 矩形 / 圆 / 椭圆 / 自由形状 / 路径 / 点）→ 生成「未分类区域」→ 再赋予业务类型（水面、绿地、道路、建筑……）→ 点击该类型下的样式预设，自动生成最终渲染对象。
2. **资产库模式（现有能力，零改动）**：从 Content Browser 选资产（GLB 等）拖放/点击放置，Ghost 预览、连续放置、InstancedMesh 合并等全部保留。

**设计准则**：Shape（几何）→ Semantic（业务语义）→ Style（视觉表现）三层完全解耦；修改任意一层不影响另外两层。

## 三、核心数据模型（RegionObject）

所有绘制产物统一为 RegionObject，三层独立存储、互不耦合：

```ts
{
  id: string;                  // region_ 前缀
  name: string;                // 默认「未命名区域 N」
  layerId: string | null;      // 赋类型时自动迁入类型默认图层
  visible: boolean; locked: boolean;
  transform: Transform;        // 复用既有 Vec3/Euler 契约

  shape: {                     // 几何层：纯形状，无业务语义
    type: 'polygon' | 'rectangle' | 'circle' | 'ellipse' | 'freehand' | 'line' | 'point';
    points: Vec2[];            // 顶点/控制点（XZ 平面）；圆/椭圆由参数化点生成后仍落此处
    baseHeight: number;        // 平面基准高度（y）
    closed: boolean;           // line/point 恒 false，面类恒 true
    options?: Record<string, unknown>;  // 圆/椭圆半径、矩形长宽、自由形状平滑度等派生参数缓存
  },

  semantic: {                  // 语义层：业务类型，与渲染无关
    type: SemanticType;        // 十类枚举（第二节 #4）
    properties: Record<string, unknown>;  // 业务参数：道路宽度、建筑高度等；面板按类型定义自动生成
  },

  style: {                     // 样式层：视觉引用
    presetId: string;          // 样式插件 id；unclassified 默认 default_solid
    overrides: Record<string, unknown>;   // 用户覆写参数（非默认值才存）
  },
}
```

- **形状类型可切换**：属性面板下拉切换（如多边形→矩形），切换后按包围盒/中心自动转换顶点；圆/椭圆编辑半径、矩形编辑长宽。
- **业务参数消费分流（2026-09-11 审计定稿，消除与 5.2 节的矛盾）**：业务参数存于 `semantic.properties`，消费方按参数分流——`road.width` 由 GeometryBuilder 读取（线状形状生成带宽面，见第五节 ②）；`building.height` 由 building 预设在 build 内挤出（见 5.2/5.4 ②），不是「全部由构建器读取」。
- **高度合成规则**：最终 y = `shape.baseHeight` + `transform.position.y`（贴地层抬升与对象变换两层叠加；「基准高度」面板读写 baseHeight、Gizmo/属性面板 Y 值读写 position.y，详见分域契约 §A）。
- **校验**：自相交/顶点不足拦截沿用现有 validateGeometry 语义，作用于 polygon/freehand；参数化形状（矩形/圆/椭圆）天然合法。

## 四、语义类型（十类）

| 类型 | 几何 | 默认图层 | 业务参数（初始） | 说明 |
|---|---|---|---|---|
| unclassified | 任意 | 未分类 | — | 绘制完成后的初始态 |
| water | 面 | 水面 | — | 湖泊/水池 |
| grass | 面 | 绿地 | — | |
| plaza | 面 | 广场 | — | 铺装广场 |
| parking | 面 | 停车场 | — | |
| bare_land | 面 | 裸地 | — | 泥土/待建区 |
| road | 线（或面） | 道路 | width | 中心线→带宽面由构建器生成 |
| building | 面 | 建筑 | height | 与水面平权的普通类型；立体感由样式预设实现 |
| poi | 点 | POI | — | 图标牌/光柱/地面标记样式 |

新语义类型的接入 = 注册制（SemanticRegistry 或扩展现有 ElementRegistry 语义），禁止框架内散落 `if (type === 'water')` 判断。

## 五、插件化样式引擎（核心架构）

### 5.1 目录与形态

- 落位 **`src/runtime/styles/`**（three 白名单内；editor/domain 层零感知）：`engine.ts`（公共入口）、构建路由注册表（`import.meta.glob` → `presetId → build` 映射，仅构建函数）、插件按 `形状类/语义分类/*.preset.ts` 组织，**同文件导出 `meta`（纯数据）与 `build`**。
- **双轨注册（2026-09-11 分层审查修订）**：预设元数据 = registries 层 `StylePresetRegistry`（纯数据，editor/ui 可读）；构建函数 = runtime 层构建路由；组合根 bootstrap 启动时收割插件 meta 注入注册表，`EditorFacade.registries.presets` 暴露——registries 永不含构建函数（DAG 方向），ui 永不 import runtime。meta 与 build 一致性由守门测试锁定（缺 build 灰显禁用、缺 meta 不暴露）。
- TypeScript 实现，`meta` / `build` 强类型契约；首版不做按预设代码分包（如需升级为 registries meta 文件 + runtime build 文件成对方案，接口不变）。

### 5.2 插件契约（每预设一文件）

```ts
export const meta: StylePresetMeta = {
  id: 'water_flow',                    // 全局唯一，如 water.flow
  name: '流动水面',
  supportedShapes: ShapeType[],        // 该预设支持的形状类型
  supportedSemantics: SemanticType[],  // 过滤显示用
  defaultParams: Record<string, ...>,  // 参数定义（键/标签/类型/默认值/min/max——沿用 StyleParameter 形态）
};

export function build(geometry: BufferGeometry, params: ResolvedParams): StyleInstance;
```

**StyleInstance 统一返回契约（强制）**：

| 字段 | 说明 |
|---|---|
| `object: THREE.Object3D` | 根渲染对象，直接挂场景节点 |
| `material: THREE.Material` | 主材质（通用批量操作用） |
| `presetId` / `supportedShapes` | 元数据回带 |
| `update(params)` | **只改参数/uniform，禁止重建几何** |
| `setGeometry(geometry)` | 形状修改后的几何重绑（v1 矛盾修正 ①） |
| `dispose()` | 释放本实例全部资源 |

插件可携带任意 ShaderMaterial（含 Shadertoy 移植）；可在 build 内做几何预处理（细分/UV/按参数挤出——building 立体预设即此路径）。

### 5.3 引擎入口（纯函数、无状态）

```ts
createStyle(geometry, shapeType, semanticType, presetId, overrides?) → StyleInstance  // 校验/合并参数/路由/构建；失败降级 default_solid + Toast
updateStyle(instance, params) / disposeStyle(instance)
```

### 5.4 四处 v1 矛盾的修正（已裁决）

1. **update/setGeometry 拆分**：参数变更走 `update`，形状变更走 `setGeometry`——解决 v1「update 只改参数」与「改形状调 update」的签名矛盾。
2. **道路带宽几何留在几何构建器**：`GeometryBuilder(shape, semantic)` 读取 `semantic.properties.width` 生成带宽 BufferGeometry；样式插件只管材质。拾取/框选/面积读数依赖真实几何在场景层。
3. **材质模板 + 覆写 clone**：同预设多实例默认共享材质模板；有 overrides 的对象 clone 独享；删除对象时引用计数释放。禁止共享材质被单对象改写。
4. **目录与语言**：`src/runtime/styles/` + TypeScript（取代 v1 的 `src/styles/` + `.js`）。

### 5.5 现有样式迁移与新增（三栏清单，2026-09-11 审计对齐代码现状 19 套）

现状 19 套（`src/registries/definitions/styles.ts`：building×5 / road×4 / green×3 / water×3 / parking×2 / marker×2，无 plaza、无 base 通用）按三栏处置，**新库合计 21 套**：

## 六、渲染管线与三类修改

```
Shape 数据 → GeometryBuilder（形状+语义参数 → BufferGeometry，XZ 平面）
           → StyleEngine.createStyle(geo, shapeType, semanticType, presetId, overrides)
           → StyleInstance.object 挂 RegionObject 场景节点
```

| 修改 | 行为 | 不变 |
|---|---|---|
| 改 Shape（拖顶点/切形状类型/改参数） | 构建器重生成几何 → `setGeometry` 重绑 | 类型、样式、overrides 全保留；不重建材质 |
| 改 Semantic（切类型） | 旧实例 dispose → 新类型默认预设 create | 几何顶点不动；自动迁入类型默认图层（一条命令内、可撤销） |
| 改 Style（切预设） | 旧实例 dispose → 新预设 create | 几何复用，只换渲染对象 |

- **跨层纪律（2026-09-11 分层审查修订）**：editor 层只修改 RegionObject 的纯数据字段（经命令 → `scene:changed` 事件），样式实例生命周期归 runtime RegionRenderer 订阅调解；StyleInstance / StyleEngine / GeometryBuilder（含 THREE 类型）仅 runtime/app 可见，editor/domain/scene/registries/io/ui 源码零 THREE（check:layers + 分域契约双守门）。
- 渲染模式（着色/线框/X-Ray）：线框与 X-Ray 以场景级 overrideMaterial 全局替换实现，含 Shader 样式在内全部被覆盖；着色模式 = 正常渲染。
- 资源纪律：dispose 完整释放（几何/材质/纹理/引用计数）；频繁操作（拖顶点）节流。

## 七、UI 交互

### 7.1 垂直工具条（重构）

```
【变换组】 Q 选择 · W 移动 · E 旋转 · R 缩放（纯字母键，不变）

```

### 7.2 三步创建流

1. **绘制**：状态栏实时长度/面积/顶点数；Shift 正交、A 45°、G 吸附沿用；进入绘制自动顶视+限制旋转沿用。
2. **生成未分类区域**：双击闭合（面）/双击结束（线）/点击即成（点）→ 创建 RegionObject（unclassified + default_solid），回到选择工具并选中新对象。
3. **赋类型与样式**：上下文工具条浮出「类型芯片（水面/绿地/广场/停车/裸地/道路/建筑/POI/更多）+ 样式缩略图快选条」；或属性面板正式操作。点击即应用，自动归层。

### 7.3 属性面板（四分组）

基础信息（名称/图层/锁定/可见）· 几何（形状类型切换、顶点数/面积/周长只读、基准高度（读写 `shape.baseHeight`，与 Gizmo Y 值读写 `position.y` 分工叠加，见第三节高度合成规则）、「编辑顶点」按钮→T6.8 前禁用占位）· 业务类型（类型下拉 + 按类型定义动态生成的业务参数）· 表现样式（预设缩略图网格按 shape+semantic 过滤 + 选中高亮；参数控件实时生效 + 四档作用域应用——作用域过滤字段映射见第二节 #9：同类型按 `semantic.type`、当前图层按 `layerId`、同预设按 `presetId`，第四档标签「同预设」）。

### 7.4 撤销重做

三种原子命令：`ChangeShapeCommand`（形状类型切换与参数化形状参数变更）、`ChangeSemanticCommand`（类型 + 自动归层合并为一条）、`ChangePresetCommand`（预设切换 + overrides 变更；命名避开 v1 同名旧命令，过渡期新旧命令按对象类型派发、v1 两条随 T6.7 退役——对照见分域契约 §D）。连续绘制段合并语义沿用。

## 九、验收标准（摘要，完整清单见各任务书）

- **功能**：七种形状可绘制并生成未分类区域；切类型无需重绘；切预设实时生效且几何不动；道路中心线体验与原版一致；建筑预设可生成立体效果；POI 三类预设可用。
- **架构**：三层独立存储无交叉依赖；样式一预设一文件、统一入口；新增样式/语义类型仅增文件不改核心；check:layers/typecheck/test 全绿（three 仅 runtime/app）。
- **兼容**：手势/Gizmo/选择/图层/大纲/撤销/资产放置零回归（以 T5.9 回归清单为基线重跑）；撤销粒度正确（改样式只撤样式、改形状只撤形状、切类型连归层一条撤销）。
- **性能**：切预设响应 < 100ms（中复杂度场景）；拖顶点期间不重建材质、帧率无明显下降；删除对象资源零泄漏（引用计数验证）。
