# 三维园区可视化编辑器需求文档


本版定位：将现有「JSON 平面图生成 \+ 模型摆放」工具升级为组件化、可拓展的三维园区编辑器。核心结论如下：

- 以 Scene 为唯一数据源，Three\.js 仅为运行时表现；任何可见状态变更必须经 Command，保证可撤销重做。

- 本期功能边界：要素预设样式切换、模型素材库与连续放置、点线面绘制三大能力闭环；Shader 编辑器、批量散布、DXF 导入等列为后期。

- 采用六层单向依赖架构与八大核心概念，并新增分层边界约束、批量命令、样式三级优先级、预览隔离等规则。

- 分三阶段落地，第一阶段优先解决「样式单一」痛点并打牢数据架构，每阶段均有可运行的验收闭环。


# 项目概述

## 项目背景与现状

## 项目目标

构建一套组件化、可拓展的三维园区编辑器：以空白场景为起点，通过绘制、资产摆放、样式选择、属性编辑、图层管理完成园区构建；外部数据导入保留为「构建加速入口」，而非必经步骤。目标工作流：

```text
新建空白场景 → 天空 + 无限地面 → 绘制点 / 线 / 面 → 生成园区要素
→ 选择样式 → 从模型资产库摆放模型 → 三维编辑 → 场景管理 → 保存 / 重新打开
```

## 范围界定

|范围|内容|
|---|---|
|本期（V2\.0）|要素预设样式系统；模型素材库与连续放置；点线面绘制模式；统一场景管理（选择、变换、属性、图层、场景树、撤销重做）；JSON 导入配置化映射。|
|明确排除（后期）|Shader / 样式编辑器；批量散布；DXF / GeoJSON 导入；顶点编辑；测量与标注；插件系统；LOD。|

# 核心设计原则

以下原则为全系统硬约束，UI、素材库、样式库、绘制器、属性面板、场景树等一切功能都建立在其上，而不是反过来推动核心架构。

|原则|核心要求|落地约束|
|---|---|---|
|Scene First|Scene 是唯一数据源，创建、导入、编辑、删除最终都作用于 Scene。|JSON 只是外部输入，不是系统核心。|
|数据与渲染分离|业务层不能拿 THREE\.Mesh 当业务对象。|业务数据与 Three\.js 运行时对象双向映射，各管各的。|
|Geometry 与 Style 分离|几何只描述位置、轮廓、尺寸、拓扑；样式只描述颜色、材质、Shader、发光等视觉。|同一建筑切换不同 Style，Geometry 完全不变。|
|2D 与 3D 同一编辑器|绘制模式只是 Camera = Top，不是另一套二维编辑器。|地面画出的点线面直接就是三维场景对象。|
|Asset 与 Element 分离|建筑、绿地、道路是 Element；树、路灯、车辆是 Model Asset；最终统一为 SceneObject。|场景只保存 Asset 引用，不保存模型文件本体。|
|所有操作可撤销|任何可能改变 Scene 的操作都进入统一 Undo / Redo 系统。|可见的 Scene 修改必须经 Command。|
|Registry 扩展机制|新要素、新工具、新样式通过注册接入。|禁止用 switch\(type\) 散落业务代码。|

# 总体架构

## 六层架构

系统严格划分为六层，依赖方向单向向下；UI 依赖 editor，editor 依赖 domain 与 scene，scene / domain 依赖 core，runtime 适配 Three\.js，io 负责数据进出。

|层|目录|职责|边界约束|
|---|---|---|---|
|core|id / events / math / utils / types|基础能力与公共类型。|不依赖任何上层。|
|scene|Scene / SceneObject / Layer / SceneGraph|纯数据容器与增删改查。|只存数据，不校验、不计算。|
|domain|Element / Geometry / Style / AssetReference|业务定义、默认值与校验。|不出现任何渲染 API。|
|editor|Tool / Selection / Command / History / Interaction|用户操作与交互编排。|修改 Scene 必须经 Command。|
|runtime|Renderer / ObjectAdapter / AssetLoader / MaterialAdapter / Cache|渲染对象创建、更新与回收。|只读 Scene 数据，不得反向修改。|
|io|SceneSerializer / Importer / Exporter|数据导入、导出与序列化。|产出 / 消费标准 SceneData。|

## 核心数据流

用户操作到渲染的完整链路：Tool 产生意图，Command 落库并进入历史，Scene 更新数据，Renderer 依据 Geometry / Style / Asset 重建运行时表现；拾取时通过 objectId 反向定位业务对象。

## 分层边界规则（不可越界）

1. Scene 层只存纯数据：SceneManager 只做增删改查，不承担校验与计算；校验放在 Domain 层，操作放在 Editor 层。

2. Runtime 层只读不改：渲染层只能读取 Scene 数据生成运行时对象，禁止反向修改 SceneObject 属性；一切修改走 Command → SceneManager 链路。

3. Domain 层不依赖渲染：Element、Geometry、Style 定义中不得出现任何 THREE 类型；业务几何经 GeometryBuilder 转换为渲染几何。

4. UI 不直接操作渲染对象：UI 只能调用 Editor 层接口，禁止直接修改 THREE\.Object3D 或 DOM。

5. 预览与业务场景隔离：DrawSession、放置 Ghost、Gizmo 等临时对象全部归 PreviewManager 独立管理，不进入正式 Scene、不产生历史记录。

6. userData 仅作运行时映射辅助，不作为业务数据源。

## 八大核心概念

|概念|回答的问题|关键约束|
|---|---|---|
|SceneObject|场景里有什么东西|所有可编辑、可保存对象的统一基类。|
|Element|这个东西在园区里是什么|有几何语义的要素，含 geometry \+ style \+ properties。|
|Geometry|它的空间形状是什么|纯数据（Point / LineString / Polygon），不是渲染几何。|
|Style|它看起来是什么样|与几何分离，可随时切换，不重建几何。|
|Asset|它引用什么可复用资源|场景只存 assetId 引用，不存模型文件本体。|
|Tool|用户现在要做什么|同一时刻仅一个激活工具。|
|Command|这次操作如何可撤销|一切可见修改必须经 Command。|
|Registry|系统如何扩展新能力|新类型 / 工具 / 样式注册接入，禁止 switch 散落。|

# 核心数据模型

## SceneObject（统一对象）

Element 与模型对象统一继承 SceneObject，保证选择、变换、图层、属性、保存等能力一致。

```ts
interface SceneObject {
  id: ID;              // 稳定业务 ID：scene_ / element_ / asset_ / style_ / layer_
  type: string;        // 类型标识（注册制）
  name: string;
  parentId: ID | null;
  layerId: ID | null;
  visible: boolean;
  locked: boolean;
  transform: Transform; // position / rotation / scale
  properties: Record<string, unknown>;
  metadata?: Record<string, unknown>;
}
```

## Transform 与坐标系统

编辑器内部统一使用世界坐标；对象统一保存 position、rotation、scale。

```ts
interface Transform {
  position: Vector3;   // { x, y, z }
  rotation: Euler;     // { x, y, z }
  scale: Vector3;      // { x, y, z }
}
```

## Element 与 ElementType

Element 是具有园区业务语义的 SceneObject。一期支持以下类型，后续通过 ElementRegistry 注册扩展，禁止在业务代码中散落类型判断。

|类型|支持几何|生成方式|一期关键属性|
|---|---|---|---|
|Building 建筑|Polygon|多边形 \+ 高度挤出|高度、底部高度、楼层、屋顶类型（一期仅挤出）|
|Road 道路|LineString / Polygon|中心线 \+ 宽度，或直接面区域|模式（centerline / polygon）、宽度|
|Green 绿地|Polygon|贴地表面|样式预设|
|Water 水面|Polygon|水面表面|透明度、波纹（后期）|
|Parking 停车场|Polygon|停车区域|停车位、车辆填充（后期）|
|Square / Wall / River / GroundArea / Custom|按几何类型|由几何 \+ 样式决定|沿用 Element 通用属性|

## Geometry（点线面）

业务几何是纯数据，不是 THREE\.BufferGeometry；渲染层经 GeometryBuilder 转换为渲染几何，未来更换渲染实现不影响 Scene 数据。

```ts
interface PolygonGeometryData extends GeometryData {
  type: 'Polygon';
  coordinates: Vec2[][];   // 业务几何数据
}
```

## Style 与样式三级优先级

Element 不复制 Style，只保存 StyleReference（styleId \+ 参数覆盖）。参数由 StyleParameter 声明驱动 UI 自动生成（颜色、滑块、开关），无需为每个样式单独开发面板。

|优先级|层级|说明|修改入口|
|---|---|---|---|
|低|全局样式预设|StyleRegistry 内置预设，定义要素默认视觉。|样式库|
|中|图层级样式覆盖|作用于整个图层，批量同步视觉。|图层面板|
|高|对象级参数覆盖|单对象微调参数，保留个性。|属性面板|

优先级从低到高，上层覆盖下层：修改图层样式时全图层同步，单独调整过的对象保留个性。

## Asset 与 AssetReference

场景中不保存整个模型文件，只保存引用。

```json
{ "assetId": "tree_001" }
```

模型文件仍位于项目 /assets/models/ 目录，由 AssetRegistry 统一扫描、加载、缓存与实例化。

## Layer 与 Scene

Layer 是 SceneObject 的组织方式（Building / Roads / Green / Water / Parking / Models / Decoration / Annotation），支持显示隐藏、锁定、透明度；Scene 保存的是数据模型，不是 Three\.js Scene。

```json
{
  "version": "1.0",
  "id": "scene_xxx",
  "name": "园区A",
  "environment": {},
  "layers": [],
  "objects": []
}
```

## Command 与 History（含批量命令）

所有可见的 Scene 修改必须经 Command，且保存 before / after 以支持撤销重做。

```ts
interface TransformCommandData {
  objectId: ID;
  before: Transform;
  after: Transform;
}
```

补充 BatchCommand 机制：将多个子 Command 打包为一个原子命令，共享一个 undo / redo 入口。连续放置模型、批量修改样式等场景默认合并为一条历史记录（是否合并可配置），避免撤销十棵树要按十次。

# 功能需求

## 场景与基础环境

- 新建场景默认包含：天空 \+ 无限地面 \+ 环境光 / 方向光 \+ 阴影。

- Ground 是绘图画板：鼠标位置经 Raycaster → Ground → 世界坐标，供绘制与放置共用。

- 环境预设：白天 / 傍晚 / 夜景 / 科技；预设可扩展，环境数据随场景保存。

## 选择、变换与属性

- 选择：单选、多选、框选、取消选择；视口与场景树双向同步。

- 变换：标准 Gizmo 支持移动 / 旋转 / 缩放，快捷键 W / E / R；修改经 TransformCommand 进入历史。

- 属性面板：基础信息、Transform、Geometry（高度等）、Style（预设 \+ 参数）、自定义属性。

- 图层与场景树：按图层组织对象，支持显示隐藏、锁定、透明度、重命名与搜索定位。

- 复制、删除：支持 Ctrl\+C / Ctrl\+V 与 Duplicate；删除进入撤销栈。

## 绘制模式

- 进入绘制模式自动切换顶视图，控制器限制旋转、开启网格与吸附；保留透视视角开关，高级用户可在透视下绘制。

- 绘制辅助：实时显示线段长度、多边形面积与顶点坐标；支持正交锁定（X / Z 轴）与 45° 角锁定。

- 点工具：左键确认后自动连续绘制，右键 / ESC 退出。

- 线工具：点击加点、移动实时预览、双击结束生成 LineString。

- 面工具：点击加点、双击闭合生成 Polygon；校验自相交与最少顶点，非法输入拦截并提示。

- 绘制过程在 DrawSession 中临时管理，完成后经 CreateObjectCommand 进入 Scene，半成品不污染正式场景与历史记录。

## 样式系统

- 一期收敛为「预设 \+ 轻量调节」，不做完整 Shader 编辑器：每种要素内置 3–5 套预设，用户切换预设并微调少量参数（颜色、透明度、高度、发光等）。

- 切换样式后 Geometry、Transform、Properties 均不变。

- 样式修改作用域：仅当前对象 / 同类型对象 / 当前图层 / 全部使用该样式的对象。

- 参数面板由 StyleParameter 声明自动生成。

|要素|一期预设样式|可调参数（示例）|
|---|---|---|
|建筑|默认建筑 / 现代建筑 / 玻璃建筑 / 科技建筑 / 夜景建筑|高度、主体色、透明度、发光|
|道路|标准道路 / 沥青道路 / 科技道路 / 夜景道路|宽度、颜色|
|绿地|草地 / 景观 / 科技绿地|颜色、起伏强度|
|水面|标准水面 / 动态水面 / 科技水面|透明度、流动速度|
|停车场|标准停车区 / 科技停车区|底色、标线|

## 模型资产库

- 自动扫描项目 /assets/models/ 目录，按分类组织：建筑、植物、车辆、人物、道路设施、公共设施、消防设施、设备、其他；支持自定义分类。

- 一期支持 GLB / GLTF，OBJ / FBX 二期扩展。

- 启动读取 manifest\.json 清单，不重复全量扫描目录；首次加载模型时自动生成缩略图并缓存，后续直接读取。

- 资产卡片 UI 支持搜索、分类、标签、排序、收藏。

- 资产元数据：id、name、category、file、thumbnail、tags、defaultScale、defaultRotation、metadata。

## 模型放置

- 点击资产进入放置模式，Ghost 半透明预览跟随鼠标（Raycast 地面）。

- 左键确认放置并保持放置模式，可连续点击多次放置；右键 / ESC 退出，不删除已放置对象。

- 放置参数：随机旋转、随机缩放（范围可配），实时预览效果。

- 放置中支持滚轮缩放预览、R 键旋转预览，无需退出模式调整。

- 同一 Asset 多实例共享几何与材质，进入 InstancedMesh 优化路径。

- 批量散布列为后期功能。

## 数据导入（JSON 配置化映射）

- 保留并升级现有 JSON 导入：通过映射配置文件定义 JSON 字段 → Element 类型、Geometry 格式、默认 Style 的对应关系；不同结构的 JSON 无需改代码即可适配。

- 导入产物必须是标准 Element，禁止直接生成不可编辑的 Mesh；导入后仍可改高度、形状、样式、属性、移动、删除。

- 导入失败给出字段定位与原因。

## 撤销重做

- 所有可见 Scene 修改经 Command 进入历史，快捷键 Ctrl \+ Z / Ctrl \+ Shift \+ Z。

- 基础命令：创建、删除、移动、旋转、缩放、改样式、改属性、改几何、改图层。

- BatchCommand 合并：连续放置、批量改样式合并为一次撤销（可配置）。

## 吸附、网格与视图

- 吸附规划：Ground / Grid / Vertex / Edge；一期先落地 Ground 与 Grid，用于建筑、道路、围墙绘制。

- 网格：支持网格尺寸、间距、显示 / 隐藏。

- 视图：自由视图、顶视图、前视图、侧视图；F 聚焦对象、Home 聚焦场景。

# 非功能需求

## 性能

- 实例化渲染下沉到 AssetRuntime 层：同一 Asset 的所有实例共用几何与材质，自动合并 Draw Call（InstancedMesh 一期实现），业务层无感知。

- 缓存体系：Asset / Geometry / Material / Shader / Texture Cache，避免重复加载。

- 预留空间索引接口（BVH / 四叉树）：场景对象规模上升后接入，不改业务代码。

- Frustum Culling 默认开启；LOD 后期按需引入。

## 数据校验

- Domain 层统一 validate：自相交、最少顶点、坐标非法等拦截并提示；简单错误（如顶点顺序）自动修复。

- 外部数据（JSON 等）导入时统一过校验管线，失败给出定位。

## 扩展性与兼容性

- Element / Asset / Style / Tool / Command 全部注册制接入，新增能力不改核心代码。

- 核心模块间通过 EventBus 解耦，UI 与 SceneManager 不直接强耦合。

- 场景文件带版本号，后续版本保证向后兼容。

# 分阶段实施计划

## 阶段一：核心骨架与样式系统

优先解决「样式单一」痛点并打牢数据架构。完成：Scene / Element / Geometry / Style 核心数据模型落地；SceneManager、Selection、History、EventBus；StyleRegistry 与每类要素 2–3 套预设及点击切换；现有 JSON 导入改造为标准 Element 输出；场景保存 / 加载。

## 阶段二：模型资产库与交互

完成：AssetRegistry、manifest 清单与缩略图缓存；PlacementTool（连续放置、右键退出、Ghost 预览、随机参数）；Transform Gizmo、属性面板、图层与场景树；InstancedMesh 渲染优化。

## 阶段三：绘制能力闭环

完成：DrawPoint / DrawLine / DrawPolygon 工具与 DrawSession；顶视图切换与绘制辅助（长度、面积、正交锁定）；PreviewManager 预览隔离；BatchCommand 合并撤销。

## 阶段总览与验收

|阶段|核心目标|完成内容|验收标准|
|---|---|---|---|
|阶段一|数据架构升级，解决样式痛点|核心数据模型、StyleRegistry、JSON 导入改造、场景保存加载|导入 JSON 生成建筑后可点击切换预设样式，修改高度可撤销重做，保存重开完整恢复|
|阶段二|升级模型系统与编辑交互|素材库、连续放置、Gizmo、属性面板、图层场景树、InstancedMesh|从素材库连续放置多棵树可一次撤销，选中模型可变换、改属性，场景重开恢复|
|阶段三|补齐绘制能力，形成完整闭环|点线面绘制、顶视图、绘制辅助与校验、BatchCommand|从空白场景直接绘制建筑与道路，非法多边形被拦截，绘制过程不污染历史|

## 阶段一验收流程

```text
新建场景 → 天空 + 无限地面 → 导入 JSON 生成建筑 → 点击建筑切换样式
→ 修改高度 → Ctrl+Z 撤销 → 打开资产库选择树模型 → Ghost 预览
→ 连续点击放置 3 棵 → 右键退出 → 选中树移动 / 旋转 / 缩放
→ 保存场景 → 重新打开 → 场景完整恢复
```

# 风险与开放问题

|风险 / 问题|影响|应对 / 待确认|
