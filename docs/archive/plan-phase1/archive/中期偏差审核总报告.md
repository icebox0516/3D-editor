## 五、后续执行风险提示

1. **收口争议风险（最高优先）**：无主需求债若不在阶段 7/8 门中裁决，项目收口时将转化为验收争议源——ui升级 P1 条目字面仍在，届时外部干系人只读需求文档即可得出「未兑现且无裁决」的结论。C1 门宜早不宜晚。
2. **真相源失真级联**：后续任务简报与子代理派发均依赖 STATUS 上下文，数字失真会向下游任务传递（例如子代理按「1343」校验测试基线会产生误报）。C3 必须在 T7.3 派发前完成。
3. **暂裁执行惯例化**：VertexEditSessionPort 是首例「暂裁执行」。若挂账长期不闭且后续效仿，将侵蚀按需门机制的权威。建议规则化：「暂裁执行最多跨越一个任务周期，逾期必须强制追认或回滚」。
4. **阶段 7 后半程交互回归**：T7.5（多选批量）与 T7.6（对齐/阵列/道路工具）是 P1 剩余最大块，历史模式显示 UI 任务易在 GUI 验收暴露交互回归；T7.8 全量回归通过前，不得提前对外宣布阶段 7 完成。
5. **串行链对门响应的依赖**：项目为纯序依赖制、无日历里程碑，节奏完全取决于门裁定响应速度。T8.1 任务书当前仍为粗粒度「阶段门前定稿」——建议在 T7.4–T7.6 执行期间提前定稿，避免阶段 8 开工被定稿延迟阻塞。
6. **节奏不可外推**：4 天 40 任务含 3 个 GUI 验收里程碑的节奏属于高强度运行，不应以此为基准对剩余 12 项任务（含两个整阶段验收）做工期承诺。
