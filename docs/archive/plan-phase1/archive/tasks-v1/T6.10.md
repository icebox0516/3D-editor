### 关键技法（踩坑沉淀，新会话少走弯路）

1. **run_js 包装函数非 async**：await 需 promise 链 + `window.__x` 暂存，下一调用读回（方法学 18②）。
2. **强制单帧**：canvas 派发 `webglcontextlost`(cancelable)+`webglcontextrestored` 事件对 → Watchdog onRestored → `renderFrame()` 同步执行；**toDataURL 必须同任务**。桥页 fps 读数不涨（冻结）但 `SlidingFrameCounter.tick` 补丁（import `/src/runtime/renderLoopStats.ts`）证实每对事件恰 +1 帧。
3. **three 双实例坑**：`import('/node_modules/.vite/deps/three.js')`（无 ?v= 哈希）= 第二实例，原型补丁无效；真模块 = `/node_modules/.vite/deps/three.js?v=564b655a`（resource timing 可查）。**src/** 模块（/src/runtime/Renderer.ts 等）直接 import 即同实例，优先补丁这些。
4. **场景引用捕获**：补丁真模块 `Object3D.prototype.add` → 切一次预设触发 reconcile → 沿捕获 ref 爬 parent 到 Scene；camera 经补丁 `/src/runtime/Renderer.ts` 的 `Renderer.prototype.renderFrame` 捕获 `this`。
5. **对象身份断言**：`sceneRef.traverse` 按 `userData.objectId`（RuntimeObjectMap 写入）定位；根组 name=「未命名区域 N」；分块读回 PNG 后 `md5sum` 比对防陈旧帧（14b）。
6. **FPS 口径**：冻结下 `getViewportStats().fps` 恒 0；F 项 FPS 测量须用 tick 补丁计数（每次强制帧 +1）或待宿主解冻后用 IAB 实测——验收措辞可按「冻结环境限制+逻辑帧证明」处理，属方法学增补候选。
7. **渲染模式菜单**：HUD 按钮标签随当前模式变（Shaded→Wireframe→X-Ray），**按 `title="渲染模式"` 匹配**；菜单为状态机（连点开合，18⑥）。
8. **顶视相机旋转 90°**：画布 x→地面 y、画布 y→地面 x（画布中心≈原点，约 5.5px/m）——椭圆两段拖拽方向受此影响（X 半轴沿画布 x 拖、Y 半轴沿画布 y 拖即可）。
9. **数字键/键盘不可达**（沿 4b）：数字键切工具/ESC 退出用 DOM 按钮等价；主菜单/子工具菜单/渲染模式菜单均为状态机，开→flush（下一 run_js 调用）→点叶子项。
10. **Read 工具对桥页 PNG 内联显示失败**（CDN 上传成功但不渲染）：像素判读用 `mcp__4_5v_mcp__analyze_image`（对 CDN URL 可用）；PNG 本地完整性可用 node zlib inflate 校验（曾误判，实际完好）。
11. **分块传输在粗暴 kill 后不稳定**（空块/RPCERR 交错）：用 chunk-safe.mjs（16KB+校验+重试）；避免在分块循环中途 kill。
