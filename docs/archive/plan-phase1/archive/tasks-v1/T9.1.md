## 现状基线（2026-09-14 只读勘察，证据带行号）

- **z-index 令牌刻度健在**：`src/ui/styles/tokens.css:131-134` 四档 `--z-panel:10 / --z-hud:20 / --z-popover:100 / --z-toast:1000`；全仓 14 处声明均走令牌或 `calc(令牌+1)`（`src/ui/styles/app.css:109/456/695/763/868/1023/1038/1113/1262/1389/2100/2113/2125/3192`），TS/TSX 零内联 zIndex——**刻度无违例**。
- **病根：弹层被困宿主层叠上下文**。五大工具条/面板均为带 z-index 的 grid item（grid/flex item 的 z-index 对 position:static 同样生效并自成层叠上下文）：`.ed-contextbar`(app.css:109)、`.ed-vtool`(456)、`.ed-menubar`(763)、`.ed-panel`(1262)、`.ed-statusbar`(3192)。全仓**零 portal**，所有菜单/下拉/tooltip 内联渲染在宿主内部——其 z100 只在宿主内有效，对外等效 z10，再按 App DOM 顺序（`src/App.tsx:728-824`）与同级后来者比拼：
  - MenuBar 下拉（`src/ui/menus/MenuBar.tsx:244`）被 DOM 靠后的 contextbar 盖住顶部约一项（同 z10、34px 高不透明条）；LayoutMenu（`src/ui/menus/LayoutMenu.tsx:237`）同理；
  - ContextToolbar 模式下拉（`src/ui/components/ContextToolbar.tsx:399`）与 ContextActions 对齐/阵列弹层（`src/ui/components/ContextActions.tsx:265,382`）困在 contextbar z10，压不过视口内 z20 的 HUD 芯片（`src/ui/hud/ViewportHUD.tsx:84` 恰在下拉正下方）；
  - VerticalToolbar flyout/「更多」抽屉（`src/ui/components/VerticalToolbar.tsx:203,300`）困在 vtool z10，盖不过 DOM 靠后的左面板列（App.tsx:756）；
  - Tooltip（`src/ui/components/Tooltip.tsx:74`）困在宿主工具条内，右缘按钮向右弹出会钻左面板下面。
- **裁剪伴生问题**：主菜单子弹层 absolute 锚在自带 `max-height:70vh; overflow-y:auto` 的父弹层内（app.css:861-862 × 947-959），向右展开被裁剪/挤出滚动条；Outliner「创建对象」下拉（`src/ui/panels/OutlinerPanel.tsx:426`）被 `.ed-panel`/`.ed-side` 的 overflow:hidden（app.css:1261/1271）垂直裁剪（仅宽度有防护，3023 行注释）。
- **唯一正确先例**：右键菜单 `.ed-context__popup` fixed（app.css:962-966）+ App 尾部挂载（App.tsx:818），子菜单同 fixed 且注释明说「不随父滚动裁切」（app.css:973-975）——本任务的统一样板。
- **规范缺口**：DESIGN.md 无层叠专章（仅 :120/:204/:205 顺带提及）；无「浮层必须逃逸宿主层叠上下文」「带 z-index 容器内禁渲染浮层」「calc 加码需登记」任何约定——本缺陷属规范缺口而非违例。现存两处未登记 `calc(+1)`：dialog（app.css:1038）、splitter（app.css:1389）。
- **pointer-events 现状正确非病因**：HUD 容器 none + 菜单 auto（app.css:2126/2220-2222）、toasts none+auto（1114/1129）、tooltip none（707）——不动。
- **测试现状**：z-index/stacking 全仓零断言；「GUI 效果留浏览器验收」为既定方针（Tooltip.tsx:10-11 注释先例）。

## 任务清单

### 1. 弹层逃逸层叠上下文（核心）

- **统一挂载策略**，沿右键菜单 fixed 先例，两种实现路线由子代理按改动成本择一（验收只认结果语义：弹层在任意工具条/面板/HUD 之上正确叠放）：
  - 路线 A：弹层统一 portal 到 App 根部浮层容器（新建挂载点，z 取 `--z-popover`）；
  - 路线 B：全员 fixed 定位 + 尾部挂载（ContextMenu 样板推广）。
- **覆盖清单**（七处）：MenuBar 下拉与子弹层、LayoutMenu 弹层、ContextToolbar 模式下拉、ContextActions 对齐/阵列弹层、VerticalToolbar flyout 与「更多」抽屉、Outliner「创建对象」下拉。
- **锚定语义不变**：贴锚展开、翻边、对齐逻辑维持现状——只换挂载层，不改交互行为与视觉形态。
- **Tooltip 取舍注记**：纯 CSS 贴靠方案（Tooltip.tsx）逃逸成本较高——可裁「保留 CSS 方案 + 换边避让」（近面板侧向内弹）或一并逃逸，二选一在返回报告中说明理由并落 DESIGN.md 专章。

### 2. 裁剪伴生修复

- 主菜单子弹层不再被父弹层滚动容器裁剪；Outliner 创建下拉近面板底部不被裁剪（逃逸后自然解决，或补垂直翻边）——随 §1 一并交付，验收单列。

### 3. z 刻度规范落档（DESIGN.md 层叠专章）

- 四档令牌语义表：各档合法使用者清单（panel=结构性 chrome / hud=视口内浮层 / popover=逃逸弹层 / toast=通知顶层）。
- 两条硬规则：①一切弹层必须逃逸宿主层叠上下文（portal 至根部浮层容器或 fixed）；②带 z-index 的 grid/flex 工具条容器内禁止渲染浮层。
- calc 局部加码登记制度：现存两处（dialog 101 / splitter 11）入册，后续新增须登记。

### 4. 测试

- 挂载策略中可 node 单测的纯逻辑（如弹层挂载目标解析/容器注册）单测锁定；视觉叠放关系留 T9.3 像素验收（沿既定方针）。

## 明确不做

- pointer-events 策略重构（勘察确认现状正确）；
- 四档令牌数值重调或新增档位；视觉语言（色板/间距/字体/图标）任何变更；
- 引入定位浮层库（floating-ui/popper 等）——自研 CSS 先例延续；如实现中论证必要，停下走按需门；
- T7.2 面板 Docking/Floating/Auto Hide（远期池，2026-09-14 用户预裁关闭，不动）；
- backdrop-filter 等其余层叠上下文源清理（当前无受害后代，专章注记即可）。
