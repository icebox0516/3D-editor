## 注入提示词（原文）

> 把前面实现的所有模块串联起来，跑通阶段一的完整闭环，验证架构的正确性。
>
> 【验收流程必须跑通】
> 1. 新建场景：初始化 SceneData，包含默认天空、无限地面、默认图层
> 2. 导入 JSON：调用 JSONImporter，导入一份建筑多边形数据，生成 BuildingElement
> 3. 样式切换：选中建筑，调用 ChangeStyleCommand 切换不同建筑样式，几何不变
> 4. 修改高度：修改建筑 height 属性，通过 ChangePropertyCommand 执行，渲染实时更新
> 5. 撤销重做：Ctrl+Z 撤销修改，Ctrl+Shift+Z 重做
> 6. 模型放置：从 AssetRegistry 取一个树模型，用 PlacementTool 连续放置3个
> 7. 保存加载：序列化场景为 JSON，反序列化后重新加载，所有对象完整恢复
>
> 【核心校验点】
> - 全程没有任何地方直接操作 THREE.Mesh 的 position/scale 等属性
> - 所有修改都有 Command 记录，都可以撤销
> - 重新加载场景后，所有属性、样式、位置完全一致
> - 导入的建筑和手绘的建筑是同一种数据结构
>
> 【任务】写出串联的入口代码和调用示例，标注每个环节的数据流，验证分层边界没有被突破。

## 偏差与补充（优先级高于上方提示词）

- 提示词验收含 Gizmo 拖拽——Gizmo 属 T2.4；本任务变换验收经属性面板数值输入（同样走 TransformCommand）。
- **占位资产生成提前到本任务**（原属阶段二，验收需要）：`scripts/generate-assets.mjs` 纯 Node 手写 glTF 2.0 Binary（12 字节头 + JSON chunk + BIN chunk），不依赖 three，生成 8 个低多边形占位模型 + `assets/manifest.json`：tree(植物)、streetlight(道路设施)、car(车辆)、person(人物)、bench(公共设施)、extinguisher(消防设施)、sensor(设备)、pavilion(建筑)；每个模型含顶点法线与基础色材质；`package.json` 增 `assets:generate` 脚本。
- **本任务是全编辑器 UI 设计奠基（用户指定）**：先读 frontend-design 技能，确立美学方向（建议方向：专业三维工具的暗色工作台风格，高密度、层级清晰、单一强调色——最终按技能准则定夺），产出设计系统 `src/ui/styles/tokens.css`（色板/字体/间距/圆角/阴影变量）+ `src/ui/styles/DESIGN.md`（设计方向说明）。全部面板按该系统实现，禁止通用默认样式。
- bootstrap：`src/app/bootstrap.ts` 装配 EditorFacade（8 个默认图层：Building/Roads/Green/Water/Parking/Models/Decoration/Annotation；环境预设表 白天/傍晚/夜景/科技，默认「白天」）。
- 最小 UI（仅阶段一验收所需）：顶部工具条（撤销/重做/保存/打开/导入 JSON）、左侧资产迷你列表（读 manifest，点击进入放置模式）、右侧属性面板（Transform 数值输入 + 样式预设下拉 + 高度输入）；样式参数面板自动化生成留 T2.4。
- `src/ui/store.ts`：zustand 桥接 EventBus（selection/history/tool/scene 版本号）。
