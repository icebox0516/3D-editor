## 注入提示词（原文）

> 实现编辑器的 Command 命令体系和 History 历史管理，严格执行「任何可见的场景修改都必须通过 Command」。
>
> 【核心约束】
> 1. 禁止任何地方直接修改 Scene 数据，所有变更必须通过 Command 执行
> 2. 所有命令都保存 before/after 数据，支持完整撤销和重做
> 3. 命令执行后通过 EventBus 广播事件，UI 和渲染层响应事件更新
>
> 【任务】
> 1. Command 基础接口：id/name/execute/undo/redo/canExecute；CommandContext：sceneManager/runtime/selection/history
> 2. 基础命令：CreateObjectCommand / DeleteObjectCommand / TransformCommand（before/after 两个 Transform）/ ChangePropertyCommand / ChangeStyleCommand / ChangeGeometryCommand / ChangeLayerCommand
> 3. BatchCommand：多个子 Command，execute/undo/redo 批量执行，合并为一次撤销记录
> 4. HistoryManager：execute(command) 入栈；undo()/redo()；canUndo()/canRedo()/clear()；维护撤销栈和重做栈
>
> 【输出要求】每个命令单独文件，HistoryManager 统一管理，命令执行成功后触发 scene:changed 事件。

## 偏差与补充（优先级高于上方提示词）

- CommandContext 按 CONTRACTS.md：`{ sceneManager, selection, eventBus }`——**不含 runtime/history**（命令经事件驱动渲染，History 由调用方持有；避免循环依赖）。
- 命令执行成功后除具体事件外统一 emit `scene:changed`（source=命令名）；HistoryManager 每次栈变更 emit `history:changed`（canUndo/canRedo）。
- execute 失败（对象不存在等）返回 false 且不入栈。

## 验收标准

- 每条命令 execute→生效→undo→完全回 before→redo→after（对象删除恢复后 id 不变、transform 逐字段比对）。
- execute 返回 false 不入栈。
- BatchCommand：3 个 CreateObject 一次 undo 全消失、一次 redo 全恢复；半路失败回滚已执行子命令。
- HistoryManager：空栈 undo() 返回 false；execute 清空 redo 栈；history:changed 参数正确。
- 守护三连全绿。
