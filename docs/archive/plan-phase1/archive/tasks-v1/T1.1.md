## 注入提示词（原文）

> 帮我搭建一个三维园区编辑器的核心项目骨架，严格遵循六层单向依赖架构：core -> scene -> domain -> editor -> runtime -> io。
>
> 【核心约束】
> 1. 全程严格遵守「业务数据与 Three.js 渲染对象彻底分离」原则，业务层绝对不能直接操作 THREE.Object3D
> 2. 所有层单向依赖，下层不能依赖上层
> 3. 纯 TypeScript 实现，只输出逻辑代码，不做 UI
>
> 【任务】实现 core 层全部基础能力：
> - types：定义 ID 类型（string）、Vector3、Euler、Transform 基础接口
> - id：实现 createId 函数，生成 scene_xxx / element_xxx 格式的稳定业务ID
> - events：实现 EventBus 事件总线，支持 on/off/emit，事件类型用字符串枚举
> - math：基础向量运算工具（只做业务计算用，不用替代Three.js数学）
> - utils：基础工具函数
>
> 【输出要求】每个文件输出完整的 TS 代码，带类型定义，注释清晰标注每个模块的职责和边界。

## 偏差与补充（优先级高于上方提示词）

- EventBus 用 CONTRACTS.md 的类型化 `EventMap`（`on<K extends keyof EventMap>`），不是松散 string 枚举。
- math 工具必须含：`dist2 / polylineLength / polygonArea / pointToSegmentDistance / segmentsIntersect`——绘制辅助（T3.2）与几何校验（T1.2/T3.1）都依赖，现在就要有。
- utils 含：`deepClone`（结构化克隆语义）、`clamp`、`degToRad`。
