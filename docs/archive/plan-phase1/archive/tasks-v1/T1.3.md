## 注入提示词（原文）

> 实现整套 Registry 注册扩展体系，这是系统的扩展入口，严格遵循「注册-定义-工厂-实例」的模式。
>
> 【核心约束】
> 1. 所有类型判断都通过 Registry 完成，业务代码里禁止出现 if(type === 'building') 这种硬编码判断
> 2. 新增要素、样式、工具只需要注册，不需要修改核心代码
>
> 【任务】在 registries 目录下实现 5 个 Registry：
> 1. ElementRegistry：register/unregister/get/has/list/create；接收 ElementDefinition 定义：type/label/geometryTypes/createDefault/createRenderer/validate/serialize/deserialize；create 根据 type 生成对应 Element 实例
> 2. StyleRegistry：register/unregister/get/list/findByType；管理 StyleDefinition，支持按类型查找
> 3. AssetRegistry：register/unregister/get/list/findByCategory/search；支持分类和关键词搜索
> 4. ToolRegistry：register/unregister/get/list；管理 Tool 实例
> 5. CommandRegistry：register/create；按类型注册命令工厂
>
> 【附带实现】BuildingDefinition 注册示例，含 createDefault 返回默认 BuildingElement。
>
> 【输出要求】每个 Registry 单独一个文件，全部用 TypeScript 实现，带完整类型。

## 偏差与补充（优先级高于上方提示词）

- **（重要）提示词的 `ElementDefinition.createRenderer` 移除**——它让 Domain 碰渲染，违反分层规则「Domain 零渲染」。渲染器由 runtime 侧 `RendererRegistry`（T1.4）按 elementType 注册。ElementDefinition 只保留 CONTRACTS.md 契约中的字段。
- 注册 5 类要素定义（building/road/green/water/parking）。
- 注册每类要素预设样式（按需求文档表格）：建筑 5 套（默认/现代/玻璃/科技/夜景）、道路 4、绿地 3、水面 3、停车场 2；样式定义集中在 `src/registries/definitions/styles.ts`。
- BuildingDefinition 的 createDefault：默认高度 10、baseHeight 0、floors 3、style 指向 `style_building_default`。

- `StyleRegistry.findByType('building')` 返回 5 套。
