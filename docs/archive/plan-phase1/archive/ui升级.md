# 园区三维编辑器 UI 与交互重构需求文档

**需求类型：编辑器信息架构与交互体系整体重构**  
**产品类型：园区三维场景编辑器 / 数字孪生场景生产工具**  
**核心目标：以专业三维编辑器架构为基底，兼顾园区场景编辑效率，实现“底层架构专业、操作流程高效、界面层级清晰、后续扩展可控”的整体升级。**

---

# 一、项目概述

## 1.1 项目背景

当前园区三维编辑器采用较为典型的“全功能平铺”页面结构，场景树、资产、绘制工具、图层、网格、对象属性等功能同时出现在主界面中。

该结构虽然能够快速暴露功能，但随着编辑能力不断增加，页面逐渐出现以下问题：

- 三维视口空间被大量面板占用；
- 不同层级的功能被混杂展示；
- 高频编辑操作路径较长；
- 工具常驻导致界面拥挤；
- 资产、场景、属性、绘制之间职责不清；
- 用户难以形成稳定的三维编辑操作习惯；
- 新功能继续增加后，现有布局将进一步失控。

因此，本次重构不是普通的 UI 美化，而是针对**产品信息架构、工作模式、面板体系、工具逻辑和三维交互体系**进行整体升级。

---

## 1.2 重构目标

将现有产品从：

> **“带三维视窗的园区管理后台”**

升级为：

> **“以三维视口为核心的专业园区场景编辑器”**

最终形成类似 Unreal Engine、Blender、Unity 等专业工具的基本工作逻辑，同时针对园区场景搭建进行简化和优化。

---

# 二、产品定位

## 2.1 产品定位

**轻量级专业园区三维场景编辑器**

以成熟三维编辑器的工作逻辑为基础，重点解决：

- 园区场景搭建；
- 建筑编辑；
- 道路绘制；
- 绿地、水面、停车场等空间元素编辑；
- 模型与资产管理；
- 场景层级管理；
- 场景对象属性编辑；
- 标注与测量；
- 后续空间分析。

---

## 2.2 核心设计理念

### 1. Viewport First

三维视口是整个编辑器的核心工作区域。

所有 UI 都必须围绕视口服务，任何面板、工具、资产区域均不得长期侵占视口主要空间。

---

### 2. Context First

功能根据：

> 当前工作模式 + 当前选中对象 + 当前操作状态

动态调整。

不要求用户同时看到所有功能。

---

### 3. Single Responsibility

每个主要面板只承担明确职责：

| 区域 | 核心职责 |
|---|---|
| Viewport | 三维场景操作 |
| Scene Outliner | 场景对象组织 |
| Layer | 图层管理 |
| Inspector | 对象属性 |
| Content Browser | 资产管理 |
| Toolbar | 当前操作工具 |
| Vertical Tool Bar | 园区高频绘制入口 |

---

### 4. Efficiency First

专业化不能以牺牲使用效率为代价。

对于建筑、道路、绿地、点位等园区高频操作，应尽可能减少菜单层级和鼠标移动距离。

---

### 5. Extensible

新增功能必须有明确归属。

新能力应被归入：

- 工作模式；
- 面板；
- 工具组；
- 对象属性组；

而不是直接增加一个永久按钮。

---

# 四、默认空间比例

默认工作区尺寸建议：

| 区域 | 默认尺寸 | 可调整范围 | 状态 |
|---|---:|---:|---|
| 左侧 Scene | 260px | 180~420px | 可隐藏 |
| 右侧 Inspector | 320px | 240~480px | 可隐藏 |
| 底部 Content Browser | 60px | 60~320px | 可隐藏 |
| 左侧垂直工具条 | 48~56px | 固定 | 常驻 |
| Viewport | 自适应 | 最大化 | 核心区域 |

默认情况下：

> **Viewport 建议占整个编辑区 65% 以上。**

当用户隐藏左右面板时，Viewport 自动扩展，不保留无意义空白。

1. Context Toolbar 自动更新；
2. 相关工具进入可用状态；

# 三十七、性能与体验要求

由于该页面属于三维场景编辑器，UI 重构不得明显影响 Three.js / WebGL 场景性能。

要求：

1. UI 面板展开和收起不导致 Viewport 长时间卡顿；
2. 大量场景对象下 Outliner 支持高效滚动和搜索；
3. Content Browser 采用缩略图懒加载；
4. 不因 UI 状态更新重复初始化三维场景；
5. Inspector 参数变化只更新必要对象；
6. 面板开关不应销毁和重建 Viewport；
7. 大量对象情况下选择、隐藏、锁定等操作保持可用。

# 四十四、最终设计判断标准

而不是：

第一工作流应该是：

> **Content Browser → Viewport → Inspector**

而不是：

> 在页面不同区域之间频繁切换。

### 用户增加功能

第一原则应该是：

> **进入对应模式或上下文。**

而不是：

> **再增加一个按钮。**

# 四十六、最终产品定义

本次重构的核心不是：

> **把原页面重新设计得更好看。**

而是完成一次产品层面的转换：

```text
原产品

功能堆叠
     ↓
三维视窗
     ↓
后台式操作

            ↓↓↓

新产品

Viewport
   ↓
专业三维工作流
   ↓
上下文工具
   ↓
对象 / 属性 / 资产
   ↓
园区业务能力
```

最终产品应形成：

> **“专业三维编辑器底层架构 + 园区场景高频编辑能力 + 可持续扩展的工作模式体系”**

三项能力共同构成产品基础。

**最终设计原则归纳为一句话：**

> **让用户始终围绕三维场景工作，而不是围绕 UI 面板工作。**
