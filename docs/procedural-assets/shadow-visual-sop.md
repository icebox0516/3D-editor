## 1. Shadow 公共能力使用规范

### 1.1 契约事实（T009.5 落地）

`InstanceSource`（`src/runtime/instancing/InstancedAssetPool.ts`）两个可选字段：

| 字段 | 语义 | 实装状态 |
|---|---|---|
| `customDepthMaterial?: THREE.Material` | 影 pass 专用深度材质（叶影裁切通道）。源声明时池在**三个建网格点**（singleMesh / instancedMesh / 诊断亮网格）挂 `mesh.customDepthMaterial`；**undefined 不赋值保持 three 缺省**（GLB/旧资产行为零变化）；锚点装饰 Mesh 不挂（不进场景仅包围盒） | 已实装，夏栎首验 |
| `customDistanceMaterial?: THREE.Material` | 点光源影距离材质 | **仅类型占位**：零实装零消费零 dispose；点光源影需求立项时按 customDepthMaterial 同规则一并实装，不要提前消费 |

资源语义：**全部字段归源所有**——与 geometry/material 同生命周期，源端统一 dispose，消费方（池/散布/Ghost/舞台）只挂引用。build 契约（`src/runtime/procedural/types.ts`）：**每次调用构造新材质**（不得返回模块级共享对象——缓存会 dispose 所持资源），所有权随调用移交调用方。

### 1.2 分口径（三种消费方，分开验收不绑成一项）

| 消费方 | 要求 | 验收口径 |
|---|---|---|
| **正式放置对象（产品路径）** | **必须支持 Shadow**：投影（castShadow/receiveShadow，池建网格点已统一设置）+ 叶形裁切——alpha 资产必须提供 customDepthMaterial，否则影退化为整卡剪影 | 产品路径（放置命令管线 → 池）逆光机位 + 影近景取证（§3 BS22/SC15） |
| **Ghost / Preview** | **不破坏 Shadow 契约、不要求投影**（预览态不强求 castShadow，避免预览与编辑场景产生额外阴影干扰） | Ghost 激活态：自身不投影、已放置对象影完好、无渲染异常 |
| **散布（ScatterChunkManager）** | **仅契约兼容**：类型通过、无行为破坏（T003 冻结口径——只契约必要行触碰，不做新 Scatter 功能） | typecheck 过即证；行为零触碰 |

GLB 端（AssetLoader）= 类型兼容零行为变化：GLB 源不设新字段 → 池不赋值 → 构造性逐位不变（单测锁定「不带时 undefined」路径）。

### 1.3 dispose 语义清单

| 端 | 位置 | 语义 |
|---|---|---|
| 源缓存 | `ProceduralSourceCache.releaseSource` | evict/dispose 共用路径，释放 customDepthMaterial 恰一次 |
| 缩略图 | `ThumbnailCache.captureProcedural` finally | 捕获完成无论成败均释放 |
| DEV 舞台 | `tree3aStage.disposeSource`（各资产舞台同构自持源） | 舞台自建源同口径释放，unmount 幂等零泄漏 |
| **池（InstancedAssetPool）** | 全部生命周期点 | **禁止 dispose**——源所有权原则（单测 spy 反向断言锁定） |

### 1.4 深度材质工程要点（资产作者侧；先例 `createTree3aLeafDepthMaterial`，`tree/tree3a/tree3aMaterials.ts`）

- **单一来源**：MeshDepthMaterial + RGBADepthPacking + alphaTest，SDF alpha 与表面材质共享同一 GLSL 字符串——表面改叶形，深度自动同步，不复制粘贴。
- **多材质网格守卫**：非裁切材质组（树皮）以恒等 attribute（aLeafRand=0）走实心分支，防叶形 SDF 在圆柱 uv 域上把皮组误裁出洞。
- **LOD 档位匹配**：深度材质跟 level 走（夏栎：Mid=High SDF 同源全形 / Low=Low SDF 零噪声版）；customProgramCacheKey 分档，不与主材质混缓存。
- **风动不进 depth pass**：静态影取舍已裁定（cm 级摆幅 + 影贴图 ~16cm/texel 下不可辨）——不要自行给深度材质加风动同步。
- **成本纪律**：深度片元纯 ALU，**影 pass 不吃噪声**（影贴图全场景重绘，成本随三角总量放大）。
- **DEV 同源**：DEV 出图面消费 `source.customDepthMaterial`（与正式场景同一份深度材质，单测锁同一实例），不自建副本——DEV 出图 = 正式场景。

## 4. 性能验收流程模板

### 4.1 环境（RTX 2080 Ti 开发档）

NVIDIA RTX 2080 Ti（ANGLE D3D11）/ Chromium chrome-for-testing / WebGL2 / 1920×1080 **DPR=1** / day 预设固定灯光 / **Shadow 开启**（sun (80,120,60)，2048²，±160m）。2080 Ti 为**开发基准不作全平台承诺**；环境（GPU/驱动/浏览器/视口/DPR）必写入落档 README。

### 4.2 驱动路径

**产品放置路径**（不是仅 DEV 舞台）：放置命令管线（CreateObjectCommand×N → BatchCommand → HistoryManager → SceneSync → InstancedAssetPool）。驱动面 = DEV 句柄（`window.__*`，import.meta.env.DEV 守卫）提供 place/clear/stats/sampleFrames（30 帧预热 + nearest-rank 百分位）/setSunShadow/view，幂等（再 place 先清上次）；复现脚本归档 tools/（009.7 先例：CDP 直驱 chrome-for-testing）。布点间距保证全部实例 ⊂ shadow camera 范围（1000 棵 spacing 10 → 320m 见方 ⊂ ±160m；小规模 11m）。

### 4.3 棵数阈值表

| 棵数 | 1 | 20 | 100 | 500 | 1000 |
|---|---|---|---|---|---|
| FPS 阈值 | ≥60 | ≥60 | ≥60 | ≥45 | ≥30 |
| mean 帧时上限 | ≤16.7ms | ≤16.7ms | ≤16.7ms | ≤22.2ms | ≤33.3ms |

夏栎基线（009.7 实测）：710/426/267/82/49 FPS（mean 1.4/2.3/3.8/12.2/20.3ms；p95 2.7/3.9/6.8/29.6/33.2ms）。新资产对照本表全过 + 与夏栎基线同量级（显著劣化需归因：面数预算见 lod-spec.md）。

### 4.4 记录指标两档

| 档 | 指标 | 口径 |
|---|---|---|
| **必测** | Frame Time（mean/p50/p95/max）、FPS | 采样 ≥5000ms、预热 30 帧、nearest-rank 百分位 |
| | Draw Calls、Triangles | renderer.info；drawCalls 应**恒定不随棵数涨**（= 桶数 × [主材质组 + 影] + 环境；随棵数线性涨 = 退化逐对象 Mesh） |
| | CPU 时间 | 如实标注口径：rAF 间隔 = CPU+GPU 合并；CPU-only 分解需 Chrome tracing，未做时不作伪拆分 |
| | renderer.info 资源计数 | geometries/textures/programs——**计数非字节**；缓存持有（D19.4 设计内）与泄漏区分判读 |
| **条件测** | GPU 时间 | 仅当 `EXT_disjoint_timer_query_webgl2` 存在**且渲染循环已插桩且无 disjoint** 时记录；扩展存在 ≠ 可测——否则标 **unavailable（未测量，不作伪精确）** |
| | 显存占用 | 仅在具备可靠测量手段时记录，否则 unavailable |
| | Shadow 成本 | 以 **A/B 帧时差**计：sun castShadow OFF ↔ ON 同场景采样，差值 = 影 pass 全场景成本（夏栎 1000 棵 4.66 ↔ 12.39ms ≈ +7.7ms/帧） |

### 4.5 vsync 测量口径注意项

- 显示输出经合成器（虚拟显示器等）时 rAF 可能被恒限（先例 ~10Hz，与复杂度无关）——**vsync 开启口径不可测时不得拿合成器帧率当测量值**。
- 改 `--disable-gpu-vsync --disable-frame-rate-limit` 启动：rAF 间隔 = 单帧完整渲染能力（CPU 提交 + GPU，无 vsync 等待），阈值按 4.3 表换算 mean 上限——**严格保守口径**（不隐藏 vsync 余量）。
- 测量口径（vsync on/off/不可测）必须写入落档 README；agent-browser 无法带 flag 启动时（exit 非 0）回退 CDP 直驱。

### 4.6 资源契约五条（逐条验证）

1. **同 sourceKey 不重复创建 Geometry/Material**：满量放置后 geometries 有界（= 环境数 + 形态槽桶数，非实例数）；
2. **大数量（500/1000）保持 InstancedMesh 路径**：drawCalls 恒定不随棵数增长；
3. **不退化逐对象 Mesh**：逐对象退化时 drawCalls 应 ≥ 棵数，实测恒定即证；
4. **删除实例后无残留**：clear 后 objects=0、drawCalls/triangles 回环境基线；缓存保留槽源 = D19.4 设计内持有非泄漏，实例矩阵缓冲随池释放；
5. **连续 10 次放置/删除无持续增长**：geometries/textures/programs 逐轮恒定，零增长。

### 4.7 判读注意

max 尖峰（数百 ms 级）为偶发 GC/提交颠簸，以 p50/p95 健康度判读（1000 棵 p95 贴线但 mean 余量充足 = 过）；DEV 舞台编辑器视口 FPS 读数**不是产品路径口径**（009.6 旁观记档先例），不作验收值。

### 4.8 落档
